# 데이터 구조 — 상품 표 CSV 스키마와 프리팹 4겹 구조

이 섹션은 제안서 슬라이드 7·8·14의 "상품 표(CSV) + 정제 PLY → 자동 프리팹"을 구현 가능한 계약으로 확정한다. **상품 표 CSV와 정제 PLY는 2인 팀의 유일한 연결 인터페이스다.** 촬영·학습·정제 담당(권도훈)은 이 규격대로 파일을 납품하고, 프리팹 생성기 담당(이민건)은 이 규격만 읽어 프리팹을 만든다. 상품 수는 15종 상한(D5 기본값 — 사용자 확인 필요).

## 1. 상품 표 CSV 스키마 v1

파일: `Data/products.csv` — UTF-8, 콤마 구분, 첫 줄 헤더, `#` 시작 줄은 주석. 한 행 = 상품 1종.

| 컬럼 | 타입 | 예시 | 설명 |
|---|---|---|---|
| `id` | string | `ramen_cup_01` | 프리팹·PLY·SO 파일명의 키. 규칙 `[품종]_[형태]_[2자리 번호]` |
| `name` | string | `컵라면` | 게임 내 표시명(주문 HUD·POS) |
| `price` | int | `1500` | 원 단위 |
| `size_cm` | W·D·H | `12·12·10` | 실측 크기. 구분자 `·`/`x`/`X` 허용, 파서가 trim |
| `barcode_face` | enum | `bottom` | `bottom` \| `back` \| `side` (§4) |
| `ply_path` | path | `Assets/Splats/ramen_cup_01.ply` | 정제 완료 PLY 상대경로 |
| `scan_source` | enum | `scaniverse` | `scaniverse` \| `splatfacto` — D3 2단계 경로 추적 |
| `retake_count` | int | `1` | 재촬영 횟수. 3 이상이면 생성기가 경고 후 제외(D5 트리거) |
| `status` | enum | `prefab` | §2 상태 머신 |

```csv
# schema=v1
id,name,price,size_cm,barcode_face,ply_path,scan_source,retake_count,status
ramen_cup_01,컵라면,1500,12·12·10,bottom,Assets/Splats/ramen_cup_01.ply,scaniverse,0,live
kimbap_tri_01,삼각김밥,1300,10·4·10,back,Assets/Splats/kimbap_tri_01.ply,scaniverse,1,prefab
water_500_01,생수500ml,1000,7·7·21,side,Assets/Splats/water_500_01.ply,splatfacto,2,cleaned
```

제안서 예시(슬라이드 7)의 5컬럼(`크기(cm)`은 `size_cm`으로 개명)에 `ply_path`·`scan_source`·`retake_count`·`status` 4컬럼을 추가했다(제안 추가 — 권고 6·8: 디스코프 트리거 '재촬영 2회 초과'를 데이터로 추적하고, '표 한 줄' 주장을 실제 절차로 수정하기 위함).

## 2. status 상태 머신

`draft`(행 등록) → `scanned`(PLY 원본 확보) → `cleaned`(배경 컷아웃·플로터 제거 완료, `ply_path` 유효) → `prefab`(4겹 프리팹 생성·자동 검증 통과) → `live`(매장 배치·주문 카탈로그 등록). 생성기는 **`cleaned` 행만** 처리하며 나머지는 로그를 남기고 건너뛴다. 뒤로 가는 전이는 두 경우뿐이다: 스케일 검증 실패 시 `cleaned`로 복귀(§3), 재촬영 시 `draft`로 복귀(`retake_count` +1).

## 3. 프리팹 4겹 계약

```
P_{id}  (루트: Rigidbody + XRGrabInteractable + ProductPrefab)
├─ Splat            ① GaussianSplatRenderer (정제 PLY) — 레이어 Splat
├─ (루트) BoxCollider ② 프록시 콜라이더 — size_cm 환산
├─ BarcodeFace      ③ BoxCollider(IsTrigger, 태그 Barcode)
└─ Assets/Data/SO/{id}.asset  ④ ProductData ScriptableObject
```

- **① 3DGS 스플랫**: 보이는 외형만 담당. 스플랫에는 메시·충돌 정보가 없으므로(슬라이드 8) 레이어 `Splat`을 물리 매트릭스에서 분리해 레이캐스트·충돌 대상에서 제외한다.
- **② 프록시 박스 콜라이더**: 루트에 부착, 크기 = `size_cm`÷100(12cm→0.12). 잡기·던지기·내려놓기는 XR Interaction Toolkit이 이 콜라이더 기준으로 처리한다(섹션 05).
- **③ 바코드 트리거**: `barcode_face`가 지정한 면에 붙는 얇은 박스. 규격: 해당 면적 100% × 두께 0.02m, 면 중심 정렬(제안 추가 — "상품을 돌려 면을 대는 동작"이 판정이 되게 하는 최소 규격). 스캐너와의 트리거 충돌만 계산으로 인정한다.
- **④ ProductData(SO)**: 필드 `Id, Name, Price, SizeCm(Vector3), BarcodeFace(enum), SplatAsset, OrderCatalogFlags`. 주문 생성·정산·POS는 SO만 읽는다 — 씬 프리팹 없이도 게임 로직을 테스트할 수 있게 하는 조치(제안 추가).

## 4. 바코드 면 열거형과 배치 규칙

`BarcodeFace { Bottom, Back, Side }`. 제안서 예시엔 bottom/back만 등장하지만 페트병·캔 등 바코드가 **옆면**인 상품을 위해 `side`를 추가한다(제안 추가 — 15종 안에 음료류가 필수로 들어가기 때문). 면→로컬 방향 매핑: `bottom=-Y`, `back=-Z`, `side=+X`(앞면=+Z, 진열 방향 기준). 트리거는 프록시 박스의 해당 면 안쪽에 붙이고, 검증에서 "트리거가 프록시에 완전 포함되는지"를 반드시 확인한다(밖으로 삐져나오면 손에 닿는 순간 오인식된다).

## 5. 스케일 보정 규칙(실측 cm 기준)

1. 생성기가 PLY 로드 후 스플랫 로컬 바운딩 박스 `B`(미터)를 측정한다.
2. 축별 비율 `r = size_m / B`를 구하고 **균일 스케일 s = median(rx, ry, rz)**를 `Splat.localScale`에 적용한다. 축별 비율 편차가 ±10%를 넘으면 스캔 자체가 찌그러진 것이므로 경고 후 `status`를 `cleaned`로 되돌린다(제안 추가 — 비균일 스케일은 가우시안 형태 왜곡·정렬 불량을 일으켜 금지).
3. 프록시 콜라이더는 스캔 결과와 무관하게 항상 `size_cm` 그대로 생성한다 — 실측값이 물리·배치의 기준(제안서 비기능 "실측 크기 반영").
4. 검증: 보정 후 스플랫 바운딩 박스와 프록시 크기 차이가 축별 ±5% 이내면 통과(제안 추가 — 허용 오차).

## 6. 'CSV 한 줄 추가 → 프리팹 자동 생성' 실제 절차와 검증

제안서의 "표 한 줄 = 상품 추가" 주장은 수동 정제·재병합을 빼먹은 것이므로 다음 실제 절차로 대체한다(핵심 결정 8). ① 촬영·학습(섹션 03) → ② SuperSplat으로 수동 정제, `Assets/Splats/{id}.ply`로 저장 → ③ CSV 행 기입(`status=cleaned`) → ④ Unity 에디터 메뉴 `Tools/Product Prefab Builder` 실행 → ⑤ 자동 검증 통과 시 `Assets/Prefabs/Products/P_{id}.prefab`과 SO 생성(`status=prefab`) → ⑥ 매장 배치 + 해당 진열대 칸 재병합(섹션 07) → ⑦ `status=live`.

자동 검증 게이트(실패 시 생성 중단 + 콘솔 요약):
- [ ] 4겹 모두 존재(스플랫·프록시·바코드 트리거·SO)
- [ ] 스케일 오차 축별 ±5% 이내(§5)
- [ ] 바코드 트리거가 프록시에 완전 포함(§4)
- [ ] SO 필드가 CSV 행과 일치(id·가격·면·크기)
- [ ] `retake_count ≤ 2` (초과면 목록 제외 — D5)

## 7. 소유권과 변경 절차

- **데이터 값**(가격·크기·상태·행 추가): 권도훈 소유. **스키마(컬럼 정의)와 생성기 코드**: 이민건 소유(제안서 슬라이드 14 분담 그대로).
- 스키마 변경(컬럼 추가·타입 변경·열거값 추가)은 **2인 모두 확인 후 커밋**하며 커밋 메시지에 `schema:` 접두사를 붙인다(제안 추가 — 한 사람이 임의로 바꾸면 상대 생성기·CSV가 조용히 깨지기 때문).
- 생성기는 알 수 없는 컬럼을 만나면 경고하고, 필수 컬럼 누락 행은 건너뛴 뒤 "처리 N건 / 스킵 M건(사유)" 요약 로그를 남긴다.
