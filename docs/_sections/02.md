# 시스템 아키텍처 — Unity 6.3 LTS·URP·OpenXR·XR Interaction Toolkit·UnityGaussianSplatting

제안서 슬라이드 6의 4층 스택(원문 126-147)을 유지하되, 패키지 버전 고정·프로젝트 세팅·폴백 조건까지 "당장 설치 가능한" 수준으로 확정한다. 런타임 타깃은 Quest 3 + Link/PCVR이며(기본값 — 사용자 확인 필요), 스플랫 렌더링이 포함된 빌드는 Windows + Direct3D 12에서만 보장한다(DX11 미지원 — 업스트림 README·분석 §3-A 재확인). 72fps 측정 기준이 되는 GPU 사양 수치는 §08·09에서 다룬다.

| 레이어 | 패키지 | 버전 규칙 |
|---|---|---|
| 게임 로직 | C# 스크립트(계산·근무 흐름·정산) | — |
| 3DGS 렌더링 | UnityGaussianSplatting (aras-p, MIT/INRIA) | UPM git URL + **고정 커밋**(제안 추가) — 2023.12 개발 중단 저장소는 부유 추적 금지, 재현성은 커밋 해시가 전부 |

## 2. 설치 절차 체크리스트 (Windows, 이민건)

1. Unity Hub에서 Unity 6.3 LTS 설치 — 모듈: Windows Build Support(IL2CPP). Android 모듈은 불필요(Link 전용이므로).
2. URP 템플릿으로 프로젝트 생성(`vr-convenience-store`).
3. Package Manager → XR Plugin Management · OpenXR · XR Interaction Toolkit 설치(설치 시점 최신 안정판) → XRI **Starter Assets 샘플 임포트**(XR Origin·컨트롤러 프리팹 확보).
4. Package Manager → `+` → Add package from git URL → `https://github.com/aras-p/UnityGaussianSplatting.git`(커밋 해시 고정). 버그 수정이 필요하면 업스트림 PR이 아니라 `patches/` 폴더의 로컬 patch 파일로 관리한다(제안 추가 — 개발 중단으로 상류 반영을 기대할 수 없음).
5. Project Settings:
   - **Player → Graphics APIs for Windows → Direct3D12만 남기고 전부 제거**(DX11 잔존 시 스플랫 미렌더링).
   - XR Plug-in Management → PC 탭에서 OpenXR 선택 → Interaction Profiles에 **Touch Controller Plus**(Quest 3) 추가.
   - URP Asset: **MSAA = Off**(스플랫 렌더러 미지원), Render Scale 1.0에서 시작(저하 시 0.8 + FSR — 이슈 #145 보고 완화책).
   - **무조명 파이프라인**(제안 추가): 스플랫은 라이트·그림자·리플렉션 프로브 영향을 받지 않으므로(공식 제약), URP 에셋에서 Additional Lights·Shadow Distance를 끄고 매장 메시 조명은 캡처에 구운 톤에 맞춘다. 근거: '조명이 안 먹힌다'는 디버깅을 사전에 차단.
6. 검증: PLY 1종 임포트 → 우클릭 컨텍스트 메뉴의 Gaussian Splatting 항목으로 런타임 에셋 생성 → 씬에 `GaussianSplatRenderer` 배치 → Link 빌드로 육안 확인. 이 절차가 재계획 1주차 게이트의 "VR 렌더링 검증" 항목 그자체다(§08·09).

macOS(권도훈)는 동일 패키지 구성으로 **에디터 검수만** 수행한다(Metal에서도 스플랫 표시 지원). VR 실행·빌드 환경은 Windows 1대로 일원화한다.

## 3. 씬·컴포넌트 구성

```
StoreScene
├─ XR Origin (XRI)        — 카메라·컨트롤러, 고정 위치+텔레포트
├─ Environment            — 매장 메시(진열대·계산대·냉장고, URP)
├─ Shelves/Merged         — 진열대 칸별 병합 GaussianSplatRenderer(§07)
├─ Products/              — 개별 상품 프리팹(집는 순간 표시)
└─ Systems/
    ├─ GameManager        — 근무 루프·일차 진행
    ├─ POSController      — 바코드 판정·합계·결제
    ├─ CustomerDirector   — 손님 캐릭터 없음: 주문 HUD·바구니·음성만 구동(§06)
    └─ CatalogLoader      — 상품 표 CSV 로드(§04)
```

상품 프리팹 1개 = 4겹(슬라이드 8): 루트에 프록시 `BoxCollider` + `XRGrabInteractable`, 자식에 `GaussianSplatRenderer`(splat asset), 바코드 면에 isTrigger 콜라이더(레이어 `Barcode`), 루트에 `ProductData`(ScriptableObject) 참조. 프리팹 생성 절차와 CSV 스키마는 §03·04.

## 4. 렌더러 공식 제약의 설계 반영

| 공식 제약 | 본 프로젝트 반영 |
|---|---|
| 2023.12 이후 개발 중단 | 커밋 고정 + 로컬 patch(§2의 4) |
| 다중 렌더러는 위치 기반 대략 정렬 — heavy overlap 부정확 | '손 개별 스플랫 + 병합 진열대' 동시 가시 구간 최소화(집는 즉시 Invert 분리), 동시 가시 렌더러 수 상한 — §07 |
| 일반 반투명 오브젝트와 블렌딩 불량 | 비닐봉투는 반투명 메시 대신 불투명 셰이더 또는 스플랫으로 제작 — §05 |
| MSAA 미지원 | URP MSAA Off 고정(§2의 5) |
| Windows DX11 미지원 | Graphics API D3D12 강제(§2의 5) |

## 5. Unity 6.0(6000.0.23f1) 폴백 전환 조건

비공식 보고(Worldlabs: "aras-p 플러그인은 Unity 6.3에서 VR 미동작, 6.0 사용 권고")가 있어 1주차 게이트에서 동일 테스트 씬(스캔 3종 + 계산대 목업)을 6.3·6.0 양쪽에 빌드해 병행 검증한다. **전환 조건 — 하나라도 성립하면 프로젝트 전체를 6.0으로 재생성**: ① 6.3 + Link에서 스플랫이 검은 화면·왜곡 등으로 렌더 불가, ② XRI 잡기 등 핵심 인터랙션 파손, ③ 그 결함이 6.0에서는 재현되지 않음. 전환 시 패키지 재고정 커밋 + 게이트 프레임 재측정을 1일 내 완료한다(버전 차이만의 영향을 분리하기 위해 씬·에셋은 그대로 이식).

## 6. 기기 분담·GitHub 협업 규칙

| 담당 | 기기 | 이 섹션 기준 역할 |
|---|---|---|
| 권도훈 | macOS | 촬영·정제(SuperSplat)·상품 표·주문 데이터, macOS 에디터로 스플랫 검수 |
| 이민건 | Windows + Quest 3 Link | VR 빌드·프로젝트 세팅 관리·XR 인터랙션·통합 빌드 |

- **브랜치**: `main`(항상 빌드 가능 상태) + 작업 단위 `feature/*` 병행, 주 2회 통합 빌드 점검 시점에 merge(제안 추가 — 슬라이드 14 '주 2회 점검'의 실행 규칙화).
- **LFS**: `.gitattributes`에 `*.ply`, `*.spz`, 변환된 splat 런타임 `*.asset`을 LFS 추적. 원본·정제본·병합본을 `Artifacts/Raw|Clean|Merged/` 폴더로 구분해 두 벌 유지를 명시적으로 관리(제안 추가 — 병합본+개별본 이중 유지는 슬라이드 9의 요구).
- **씬 소유**: `StoreScene.unity`은 이민건 단독 수정, 권도훈은 프리팹·데이터 파일만 변경(제안 추가 — 2인 규모에서 씬 머지 충돌을 원천 차단하는 최소 규칙).
