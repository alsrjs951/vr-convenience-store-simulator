# 게임플레이 루프 — 손님(캐릭터 없음)·근무 흐름·정산·3일차 시나리오

> 소유자: 이민건(슬라이드 14 '손님·근무 루프, 점수·정산'). 주문 시나리오 데이터는 권도훈(§6.5). D4·D5 기본값 반영 — 사용자 확인 필요(§01).

## 6.1 손님 시스템 — 사람 없이 주문만 온다

손님은 사람 캐릭터 없이 다음 3요소로만 존재한다(D4 기본값 — 슬라이드 11 목업과 동일).

| 요소 | 구현 | 씬 배치 |
|---|---|---|
| 바구니 스폰 | 주문 상품 프리팹(§04)을 담은 `Basket`을 `BasketSpawnPoint`에 인스턴스화 | 계산대 앞 1곳(목업 5번) |
| 주문 HUD | 월드 스페이스 캔버스 — 손님 번호·주문 목록(라인 체크)·남은 시간·요구(봉투·결제수단) | POS 상단, 점원 시선 고정(목업 1번) |
| 음성 | 사전 녹음 클립 — 인사 2종·재촉 1종(타이머 50%)·이탌 1종·특수 요청 4종 (제안 추가: 분석 §3-I 사운드 공백의 최소 보완) | 스폰 포인트에서 재생 |

저폴리 캡슐 캐릭터는 확장 옵션뿐(D4). 대기열 없음 — 순차 스폰 1명 (제안 추가: 목업·2인 공수에 맞춤).

## 6.2 근무 흐름 상태 머신

일차 상태: `Intro(출근) → Shift(근무) → Settlement(정산) → DayEnd`. Shift 내부 루프(`GameDirector`):

```text
스폰 조건: 직전 주문 Complete/Timeout 후 spawn_after_prev_sec 경과
  Arrived  : 바구니 스폰 + 인사 음성 + HUD 갱신 → Waiting(타이머 시작)
  Waiting  : OnItemScanned(id)   → 해당 라인 체크(전량 체크 시 결제 가능)
             OnPaymentCompleted  → Complete(바구니 디스폰, 매출 가산)
             타이머 0             → Timeout(이탌 음성 + 디스폰, 매출 손실)
  Idle     : 손님 없는 동안 진열·폐기 과제
  일차 주문 전부 소진 → Settlement
```

스캔·결제 입력은 §05(XR Interaction)가 발행하는 `OnItemScanned`·`OnPaymentCompleted` 이벤트를 `CustomerService`가 구독한다(판정은 §05, 소비만).

## 6.3 3일차 시나리오 수치

| 일차 | 손님 수 | 스폰(직전 완료 후) | 손님당 제한시간 | 추가 과제 | 일차 종료 조건 |
|---|---|---|---|---|---|
| 1일차 | 5명 | 10초 | 150초(목업 02:30) — 초과해도 이탌 없음, 경고음만 | 없음(계산만) | 5명 완료 |
| 2일차 | 8명 | 15초 | 120초 — 초과 시 이탌 | 진열 5칸 채우기, 유통기한 폐기 3개 | 8명 소진(과제는 완료율로 정산) |
| 3일차 | 12명 | 일반 20초 / 피크(9~12번째) 10초 | 일반 90초 / 피크 60초 | 특수 요청(§6.4) | 12명 소진 |

- 1일차 첫 손님 앞에 6스텝 튜토리얼: ①잡기 ②돌려 바코드 찾기 ③스캔 ④HUD 체크 확인 ⑤봉투 담기 ⑥카드 결제 — 스텝당 하이라이트+음성 안내 (제안 추가: 분석 §3-I).
- 이탌 3명 도달 시 일차 즉시 종료(2·3일차만). 게임오버 화면 없음 — 정산이 결과를 대신한다 (제안 추가: 분석 §3-D).
- 설계 분배: 1일차 약 4분(+튜토리얼 1분), 2일차 약 4분, 3일차 약 5분 = 총 10~15분(슬라이드 4 목표). 실측은 §09 플레이테스트에서.

## 6.4 특수 요청과 디스코프 트리거

전자레인지·컵라면 물·1+1은 요구사항표 '확장'이며 **D5 디스코프 트리거 대상**: "3주 MVP가 3일 이상 지연 → 특수 요청을 3일차에서 제외". 제외 시 3일차는 피크타임 파라미터(스폰 10초·제한 60초)만으로 성립하며, 시나리오 CSV의 `special` 열을 `none`으로 일괄 변경해 반영한다(코드 무변경). 1+1은 같은 상품 2개 스캔 시 1개 금액만 매출에 반영하는 주문 라인 속성으로 구현한다.

## 6.5 정산과 시나리오 데이터(권도훈 인터페이스)

Settlement 항목: 매출 합계, 이탌 손님 수(매출 차감), 오스캔 횟수, 폐기 오탐, 과제 완료율 → 등급 S/A/B/C (제안 추가: 슬라이드 14 '점수·정산'의 최소 구현). 3일차 종료 시 3일치 누적 화면.

주문 시나리오 CSV(권도훈 작성, `DayScenarioLoader`가 읽음 — 상품 표와 별개 파일):

```csv
order_id,day,seq,spawn_after_prev_sec,time_limit_sec,payment,bag,special,items
c01_01,1,1,10,150,card,1,none,ramen_cup_01x1|kimbap_tri_01x2
c03_09,3,9,10,60,cash,0,microwave,ramen_cup_01x1
```

`items`의 product_id는 §04 상품 표와 조인하며 상품 종은 D5 상한 15종 내 샘플링. `special` 값: `none|microwave|hotwater|oneplus`.
