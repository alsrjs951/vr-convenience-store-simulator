# 렌더링 성능 최적화 — 진열대 병합·Invert 컷아웃·원거리 경량화·72fps

## 1. 목표·측정 기준 — 72fps의 정의

- **목표**: Quest 3 **Link(PCVR)**에서 72fps 유지(프레임타임 ≤ 13.9ms). 측정 기준은 Link에 연결된 **Windows PC의 GPU**(D2 기본값)이며, 매 측정 로그에 GPU 모델·드라이버·Link 인코딩 해상도를 함께 기록한다. 그래픽 API는 DX12 고정(§02).
- **고정 대표 장면 2개** — 매주 같은 시점에서 재현 가능해야 한다.
  - **S1 진열대 근접**: 진열대 A 한 칸 앞 약 30cm, 칸이 시야 대부분을 덮는 시점. 최악 오버드로 시나리오(이슈 #145 유형)의 재현 지점.
  - **S2 계산대 시점**: 슬라이드 11 목업 시점(바구니·POS 근거리 + 음료 냉장고 원거리). 실플레이 평균 부하.
- **프로토콜**: Oculus Debug Tool 성능 오버레이(또는 디바이스 연결 Unity Profiler)로 장면당 60초 × 3회. 기록: 프레임타임 p50/p95/p99, 드롭 프레임률, 가시 스플릿 합계, 렌더 스케일. 결과는 `docs/perf/perf_log.csv`에 누적한다(스키마 §5).
- **판정 기준**(제안 추가 — 이슈 #145가 '평균이 아니라 급락'을 보고하므로 평균 대신 백분위): **p95 프레임타임 ≤ 13.5ms이고 드롭률 < 1%**면 통과.

## 2. 스플릿 수 예산 (제안 추가)

이슈 #145는 15만~17.5만(소량)에서도 급락을 보고했으므로 제약은 수가 아니라 오버드로지만, 정렬·데이터 전송 비용은 수에 비례해 상한을 둔다. 초기값이며 W1 게이트 측정으로 확정·조정한다.

| 항목 | 상한 | 근거 |
|---|---|---|
| 상품 1종(정제 후) | 10만 | Scaniverse/splatfacto 원본 수백만 → 알파 컬링·decimation(§03) |
| 칸 병합본(칸당 2~3개 진열) | 30만 | 상품 예산 × 칸 깊이 |
| 장면 합계(D5 15종 기준) | 150만 | 15종 × 칸 수, 원거리 축소본 포함 |
| 원거리 칸(3.5m+) | 축소본 50% 또는 사진 판 | §3의 4단계 |

초과 시 대응 순서: 알파 컬링 재적용 → decimation → 마지막 수단 재촬영(2회 초과 시 목록 제외 — D5 트리거).

## 3. 4단계 전략 — 단계별 절차·체크리스트

### 1단계 개별 배치, 베이스라인 측정 (W1 게이트)
1. 확보 상품 전부를 개별 `GaussianSplatRenderer` 프리팹(4겹, §04)으로 배치.
2. S1/S2 측정 — 이 값이 모든 비교의 기준선.
3. 체크: S1에서 이미 p95 > 13.5ms면 오버드로 병목 확정. **2단계를 기다리지 않고 §4 완화책을 즉시 병행**(병합은 오버드로를 줄이지 않으므로).

### 2단계 진열대 Merge 병합
1. 칸 단위로 개별 PLY/SPZ를 하나로 병합 — SuperSplat 멀티 임포트 병합 또는 자체 에디터 스크립트(도구 체인은 §03 정제 단계와 공유). 칸당 렌더더 1개.
2. 상품별 로컬 배치(앞뒤 어긋남 정렬)를 병합 시점에 확정.
3. S1/S2 재측정. 개선이 프레임타임이 아니라 드로우·정렬 비용에만 있을 수 있음을 측정값으로 구분해 기록(제안 분석 §3-A).
4. 개별 원본과 병합본 2벌을 유지하고, 상품 추가 시 해당 칸 재병합까지가 '상품 추가의 실제 절차'다(§03·§04).

### 3단계 집는 순간 Invert 컷아웃 분리
- 구성: 병합 렌더더에 상품 위치마다 **컷아웃 볼륨(상품 경계 박스) + 컷아웃 텍스처**를 두고 Invert 옵션으로 '볼륨 내부 스플릿만 숨김' 방향으로 설정. 집는 순간 해당 슬롯의 컷아웃을 켜고 손에는 개별 상품 프리팹을 띄운다.

```csharp
// SplatShelfSlot.cs — XR Interaction Toolkit 셀렉트 이벤트에 연결
public void OnGrabbed(SelectEnterEventArgs _) {
    mergedSplat.SetCutoutActive(slotIndex, true); // 칸에서 숨김
    individualPrefab.SpawnAt(slotPose);           // 손에 개별 스플랫
}
public void OnReturned(SelectExitEventArgs _) { /* 역순 */ }
```

- `SetCutoutActive`는 자체 래퍼로, 실제 렌더더 API 시그니처는 W1~W2에 실험으로 확정한다(렌더더 개발 중단 상태 — §02).
- **경계 리스크 검증**(제안 분석 §3-F): 컷아웃 박스 경계에 걸친 가우시안이 인접 상품을 베거나 잔여 꼬리를 남길 수 있다. W2에 칸 1개 규모 실험 — 박스를 상품 경계 + 5~10mm 마진으로 조정하며 S1 시점 캡처 비교.
- 부수 효과: 손 개별 렌더더와 병합 렌더더가 같은 볼륨을 동시에 채우지 않게 되어 다중 렌더더 heavy overlap 정렬 아티팩트(§3-A) 회피와 방향이 일치한다.

### 4단계 원거리 경량화
- 3.5m 이상 칸(계산대에서 본 냉장고·후방 진열대 일부 — 소형 매장이라 적용 폭이 좁다는 전제, §3-A)은 50% decimation 축소본 또는 사진 판(라벨 정면 사진 1장 quad)으로 교체.
- 교체는 카메라-칸 거리 트리거에 **히스테리시스(3.0m 진입 / 4.0m 복귀)**를 둬 팝을 방지한다(제안 추가 — 집는 순간 교체 팝과 더불어 몰입 저해 요소).
- 문턱 거리는 매장 레이아웃 확정 후(§08) 실측 거리로 조정한다.

## 4. 오버드로 근본 대응 — 이슈 #145 보고 완화책 (제안 보강)

배경: 업스트림 이슈 #145 — VR에서 72fps가 최저 10fps까지 급락, 원인은 화면을 덮는 큰 스플릿의 프래그먼트 셰이더 부담(오버드로), 상류 수정 없음("not planned"). 다음 셋이 이슈에서 실제 보고된 완화책이다.

1. **렌더 해상도 축소** — OpenXR 설정의 Render Viewport Scale을 1.0 → 0.85 → 0.7 단계로 낮춰가며 S1에서 측정하고 단계별 결과로 인자를 고른다. Link 인코딩 해상도도 로그에 함께 기록.
2. **알파 컬링 임계값** — 정제 단계(§03)에서 알파가 임계값 이하인 스플릿을 삭제(안: 0.1~0.3, 상품별 최적값 기록). 낮은 알파 스플릿은 오버드로에 기여하되 시각 기여는 작다.
3. **FSR** — 해상도를 낮춘 뒤 URP 업스케일(FSR)로 선명도를 보정한다. 1번과 세트로 적용·측정.

적용 원칙: 인자 선택은 1~2단계 측정값으로 하되, S1 급락이 1단계에서 재현되면 그때 즉시 병행한다. 그 밖의 렌더더 제약 대응(§02): MSAA 미지원 → URP에서 MSAA 비활성, 스플릿 무조명 → 스플릿 구역에 그림자 캐스팅 라이트를 두지 않음.

## 5. 측정 일정 — 최적화 검증을 앞당긴다 (제안 추가)

제안서는 진열대 최적화를 5주차에 몰아 1단계 "먼저 프레임을 측정한다"와 상충했다(제안 분석 §3-A). 재베이스 일정(§08)에서 **W1 게이트에 1차 측정**(게이트 판정 항목 = S1 72fps, §09)을 두고, **MVP 직후부터 매주 통합 빌드 점검 때 S1/S2 고정 측정**을 반복해 로그를 누적한다. 기능 동결 전 주에는 쌓인 추세 위에서 최종 인자(렌더 스케일·FSR)만 확정한다.

`perf_log.csv` 스키마: `date, git_rev, scene, splat_total, render_scale, viewport_scale, fsr, ms_p50, ms_p95, ms_p99, drop_pct, gpu, notes`
