> 전제: 01 섹션 D1~D6 기본값 준거. HMD는 Quest 3 + Link/PCVR이며, **72fps 측정 기준은 W1에 실측 기록한 Link 대상 Windows PC(DX12)의 GPU 사양**으로 확정한다(사전에 사양이 확정되지 않았으므로 §5 시트의 `gpu` 칸이 판정 기준 원본이 된다). 분담은 제안서 슬라이드 14(원문 322·333)대로 품질 검증·FPS 측정=권도훈, HMD 빌드·실기기 테스트=이민건.

## 1. G1 Go/No-go 게이트 (W1 10/26–11/1, 판정 10/30 금) — 수치 판정

시험 스캔 3종 = **매트(과자 봉지)·인쇄(삼각김밥 랩)·반사(페트병·캔)** 각 1종. "스캔 가능 여부 판정"(원문 222)을 다음 네 항목으로 수치화한다(제안 추가 — 제안서에 판정 기준이 전무했으므로, 객관분석 권고 2 이행).

| ID | 항목 | Go 조건 | 부분/No-go | 조치 |
|---|---|---|---|---|
| G1-a | 스캔 품질 | 3종 모두 **HMD 착용 상태에서 계산대 거리(~50cm)에 들어 올린 상품의 브랜드명+가격 숫자 판독** 성공 | 반사 재질만 실패 | 부분 Go — 반사 재질만 splatfacto 경로(D3)로 전환, 3일 내 재검 |
| G1-b | 처리 시간 | 촬영+학습+수동 정제(배경·플로터 제거) 합계 **≤3시간/상품**(재촬영 제외, 실측 로그 근거) *(제안 추가: 3h 상한 — 15종×3h=45h를 3주 램프에 맞추려는 산정)* | 초과 | 상품 15종→12종 하향 + 정제 작업 팀원 분담 |

G1-c 측정 절차: Windows DX12 빌드 → Link 72Hz 고정 → 측정 포즈 3개 고정 → Unity Profiler 연결 녹화. **스플랫 예산(제안 추가)**: 정제 후 상품당 15만 가우시안·매장 전체 200만 상한 — 급락 원인이 스플릿 수가 아닌 화면 커버리지이므로 예산 초과분은 원거리 경량화(1/4 버전, 07 섹션)로 뺀다. 모든 완화책 적용 후에도 실패 시 메시 폴백·광택 없는 상품 한정으로 강등한다.

## 2. 주 2회 HMD 통합 빌드 점검 (화·금 — 슬라이드 14 "주 2회 통합 빌드 점검", 원문 337)

공통 체크리스트(매점검 동일 순서, 15분):

1. Windows DX12 빌드 성공 + Quest 3 Link 연결 확인
2. 씬 로드 10초 이내, 스플랫 누락 없음(진열대 칸 수 확인)
3. 핵심 체인 1회 완주: 잡기 → 회전 → 바코드 스캔 → 봉투 → 결제
4. Profiler 30초 녹화 → §5 시트에 1행 추가
5. 신규 버그 대장 등록, S0/S1 담당 배정

**버그 대장 = GitHub Issues 템플릿**(협업 GitHub, 원문 145): `id / 발견일 / 빌드# / 씬·포즈 / 재현절차 / 심각도 / 상태 / 담당 / 수정 빌드# / HMD-only(에디터 재현 불가) 여부`. 심각도 SLA: **S0** 진행 불가(당일), **S1** 핵심 루프 깨짐(다음 점검 전), **S2** 기능 저하, **S3** 외관. 주차 판정 관문: W2말 상품 자동 반입(10종), W3말 MVP 1일차 완주, W4 기능 동결(신규 기능 금지·S1 이상만 수정) — 날짜는 08 섹션 준거. 디스코프 트리거 2건(D5) 발동 여부도 이 점검에서 선언한다.

## 3. NeRF·3DGS 비교 실험 (W3말 촬영본 확정 후 — 원문 226 "NeRF · 3DGS 비교 실험")

- **입력**: splatfacto vs nerfacto는 **동일 사진 원본 세트 + 동일 test split 8장**을 Windows NVIDIA GPU에 투입한다. Scaniverse는 앱 내 촬영 완결 경로라 동일 세트 투입이 불가하므로, 같은 회전 프로토콜·조명의 '동일 조건 촬영본'으로 대체하고 이 한계를 결과표에 명시한다.
- **지표(4종)**: ① 품질 — `ns eval`의 PSNR/SSIM(nerfacto·splatfacto만 정량 가능), Scaniverse는 라벨 판독 5점 척도(정성) ② 학습 시간(동일 GPU, 분 단위; Scaniverse는 폰 처리 시간) ③ 자산 크기(PLY MB·가우시안 수) ④ VR 렌더 성능 — **3DGS만 측정 가능**(NeRF는 Unity용 실시간 렌더러가 없어 측정 불가. 대체 지표로 오프라인 렌더 속도 s/frame을 기록해 "NeRF를 실시간 게임에 쓸 수 없다"는 발표 근거로 재사용한다).
- 대상 상품 최소 2종(반사 1·매트 1), 결과 1행 = 1경로×1상품.

## 4. 실재감·멀미 설문 (W4 리허설, 체험자 ≥5인 *(제안 추가: 발표 근거 최소 표본)*)

- **실재감**: IPQ(igroup presence questionnaire) 14문항 7점 척도 — 총점 + 공간적 존재감·몰입·실재감 3요인. 제품 특화 3문항 추가(제안 추가 — '인쇄 글씨 재현' 목표의 직접 검증): "실제 편의점 상품과 같았다" / "라벨 글씨를 읽을 수 있었다" / "크기가 실제와 같게 느껴졌다".
- **멀미**: SSQ 16문항 **사전·사후 2회** 측정, 증상 점수 추이로 제안서 비기능 "멀미 최소화"(원문 116)의 달성을 판정한다.
- 프로토콜: 10~15분 3일차 플레이(원문 90) 직전·직후 설문. 기록 시트: `체험자ID / 날짜 / VR경험빈도 / 플레이시간 / IPQ_요인별 / SSQ_전후 / 가장 진짜 같았던·아니었던 상품(자유기술)`. 결과 표는 발표 슬라이드에 그대로 인용한다.
