# RTX 4070 데스크톱 학습 환경 세팅 가이드 (P0-L4)

## 2026-11-06 이 Windows PC 설치 기록

기존 Python 3.12와 별도로 `%USERPROFILE%\miniforge3\envs\nerfstudio`에 Python 3.10 환경을 구성했다. 아래 과거 설치 스크립트를 이 PC에서 다시 실행할 필요는 없다.

- Miniforge 26.9.4 / Python 3.10.22, PyTorch 2.1.2+cu118 / torchvision 0.16.2+cu118 / NumPy 1.26.4.
- Conda CUDA Toolkit 11.8, VS 2022 Build Tools의 MSVC 14.29.30133. 기존 VS 2026은 유지.
- tiny-cuda-nn v2.0(`3c7931caab7b691c6f30dffe20952ed727d935b9`)을 RTX 4070 아키텍처 89 대상으로 직접 빌드. GPU forward/backward 통과.
- Nerfstudio 1.1.5 / gsplat 1.4.0+pt21cu118. gsplat은 [공식 Windows wheel](https://github.com/nerfstudio-project/gsplat/releases/download/v1.4.0/gsplat-1.4.0%2Bpt21cu118-cp310-cp310-win_amd64.whl)을 사용한다. 일반 PyPI 패키지의 JIT 빌드는 이 조합에서 CUDA 헤더 오류가 발생했다.
- `nerfacto`·`splatfacto` 각 150회 학습과 PLY 12,970 vertices 내보내기 통과. `pip check` 통과. 정확한 패키지 목록은 [검증 환경](evidence/nerfstudio_packages.txt) 참조.
- COLMAP 4.2.1 CUDA는 `%USERPROFILE%\nerfstudio-work\tools\colmap`에 설치. `colmap -h` 실행 확인. 사진 재구성은 별도 검증 대상.
- 활성화는 현재 PowerShell 프로세스에만 적용한다. 전역 PATH·기존 Python 연결은 변경하지 않았다.

저장소 루트에서 실행:

```powershell
. .\scripts\windows\Enter-Nerfstudio.ps1
ns-train --help

# 공식 poster 데이터로 두 학습 방법과 PLY 내보내기 재검증
.\scripts\windows\Test-Nerfstudio.ps1 -MaxIterations 150
```

데이터·학습 결과·설치 로그는 `%USERPROFILE%\nerfstudio-work`에 저장한다. 150회 학습은 환경 동작 확인용이며 최종 상품 품질 평가가 아니다. 원격 SSH 및 Quest 연결은 별도 작업이다. 실제 통과 여부와 산출물은 [Windows 검증 보고서](Windows_검증_2026-11-06.md)를 기준으로 확인한다.

샘플 Drive 다운로드 실패 시 검증 스크립트는 공식 Hugging Face 미러를 사용한다. 미러의 실제 이미지 100개에 맞춰 로컬 카메라 목록을 필터링하며 원본 메타데이터도 보관한다.

설치 기준: [Nerfstudio 공식 설치 안내](https://docs.nerf.studio/quickstart/installation.html), [COLMAP 공식 배포](https://github.com/colmap/colmap/releases/tag/4.2.1).

## 1. 원격 접속 옵션 비교

| 항목 | RDP (원격 데스크톱) | Parsec | SSH |
| --- | --- | --- | --- |
| 용도 | GUI 전체 원격 조작 | GUI 전체 원격 조작(게임용 스트리밍) | 터미널 명령 + 파일 전송 |
| 화면 품질/지연 | 중간(로컬 디스플레이 압축 방식, 3D 뷰어 재생이 버벅임) | 좋음(GPU 하드웨어 인코딩, 60fps급 부드러움) | 화면 없음(텍스트만) |
| GPU/CUDA 학습 영향 | 학습 자체는 정상 동작. 단, 세션 잠금 시 화면 확인 불가 | 학습 중 실시간 뷰어(localhost:7007) 감시에 유리 | 학습 백그라운드 실행 가능 |
| Windows 요구 사항 | **호스트는 Pro 이상**(Home은 RDP 서버 불가) | Windows 10/11 (무료 개인용) | Windows 10/11 내장 OpenSSH 서버 기능 |
| 맥 쪽 준비 | 내장 `Microsoft Remote Desktop` 앱 | Parsec 공식 macOS 클라이언트 | 터미널(내장 ssh) |
| 파일 전송 | 드라이브 리디렉션(설정 필요) | 클립보드/파일 전송(설정 의존) | **scp 네이티브 지원 — .ply 전송에 가장 편함** |
| 설치 부담 | 없음(Pro인 경우) | 낮음 | 낮음(Windows 기능 1회 활성화) |

**권장 구성: SSH(주) + Parsec(보조).**

- **SSH(주)** — 학습 실행·상태 확인·`.ply` 회수를 맥 터미널에서 전부 처리. 윈도우 화면 없이 운영 가능하며 파일 전송이 가장 단순하다.
- **Parsec(보조)** — nerfstudio 웹 뷰어 화면이나 진행 상황을 "눈으로" 확인할 때만 켠다. RDP보다 3D/영상 스트리밍에 유리하다.
- **RDP** — 데스크톱이 Windows Pro 이상일 때만 고려. 화면 정지 화면 위주 확인용. Home 에디션이면 제외.
- 조합 예: 평상시 = 맥 터미널에서 `ssh`로 학습 돌리고 `scp`로 회수. 학습 상태를 눈으로 볼 필요가 있을 때만 Parsec 접속.

### 1.1 데스크톱 쪽 1회 설정

1. **SSH 서버 활성화** (Windows 설정 → 시스템 → 선택적 기능 → "OpenSSH 서버" 설치, 서비스 `sshd` 시작/자동 시작 설정) 또는 관리자 PowerShell:
   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Start-Service sshd
   Set-Service -Name sshd -StartupType Automatic
   ```
2. **방화벽**: 22(SSH) 허용 — 위 방식으로 설치하면 규칙이 자동 생성된다. Parsec은 자체 연결이라 별도 포트 개방 불필요(확인 필요 시 Parsec 공식 문서 참조).
3. **고정 주소화**: 집 공유기에서 데스크톱에 DHCP 예약(내부 IP 고정). 외부에서 접속이 필요하면 Tailscale 같은 VPN 우선 검토(포트 포워딩 노출 최소화). — 이 항목은 구성 제안이며, 실제 네트워크 환경에 맞게 조정.
4. **기본 셸을 PowerShell로 지정**(관리자 PowerShell에서 1회 — Windows OpenSSH 서버의 기본 셸은 cmd.exe이며(Microsoft Learn "OpenSSH Server Configuration for Windows", 2026-10-25 확인), 지정하지 않으면 SSH 접속 시 PowerShell이 아니라 cmd 프롬프트가 뜬다):
   ```powershell
   New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force
   Restart-Service sshd
   ```
5. 맥에서 연결 확인:
   ```bash
   ssh <윈도우계정>@<데스크톱IP>
   # 성공하면 Windows PowerShell 프롬프트가 뜬다 (4단계 미수행 시 cmd.exe — 그 경우 접속 직후 powershell 을 입력)
   ```

### 1.2 nerfstudio 웹 뷰어를 맥에서 보기 (선택)

nerfstudio 공식 문서에 따르면 뷰어는 **websocket 포트 7007(기본)**을 사용하며, 원격 실행 시 포트 포워딩이 필요하다. SSH 터널로 해결:

```bash
ssh -L 7007:localhost:7007 <윈도우계정>@<데스크톱IP>
# 이후 맥 브라우저에서 학습 로그에 출력된 https://viewer.nerf.studio/versions/... 링크(localhost:7007) 열기
```

## 2. 스크립트 실행 절차

### 2.1 사전 수동 설치 (스크립트 밖에서 1회 — 순서 중요)

공식 문서 요구 사항이므로 순서를 지킨다. **Visual Studio(C++ 빌드 도구)를 CUDA 관련 설치보다 먼저** 설치한다.

| # | 설치물 | 비고 |
| --- | --- | --- |
| 1 | NVIDIA 드라이버 (RTX 4070) | 설치 후 `nvidia-smi` 동작 확인. 출력의 "CUDA Version"이 11.8 이상이면 충분(드라이버가 지원하는 최대 CUDA 런타임 값) |
| 2 | Git | `git --version` 확인 |
| 3 | Visual Studio 2022 또는 Build Tools — **"Desktop Development with C++" 워크로드** | 공식 문서: CUDA 이전에 설치. MSVC v143 실패 시 v142(14.29) 추가 설치 필요할 수 있음 |
| 4 | Miniconda | 설치 후 PowerShell에서 `conda init powershell` 1회 실행, 터미널 재시작 |
| 5 | (CUDA Toolkit 시스템 설치) | **불필요** — cuda-toolkit 11.8은 conda 채널(`nvidia/label/cuda-11.8.0`)로 환경 안에 설치됨(공식 문서 권장) |

### 2.2 스크립트 실행

맥에서 SSH로 접속한 PowerShell(§1.1 4단계로 DefaultShell 지정 완료 상태 — 미지정했다면 접속 직후 `powershell`을 실행한다. 또는 데스크톱 로컬 PowerShell)에서:

```powershell
# 저장소를 데스크톱에 clone 해 둔 경우:
cd <저장소>\scripts\windows
Set-ExecutionPolicy -Scope Process Bypass -Force
.\nerfstudio_setup.ps1
```

- 학습 반복 수 변경(기본 150, 요청 범위 100~200): `.\nerfstudio_setup.ps1 -MaxIterations 200`
- 의존성 설치를 건너뛰고 검증만 재실행: `.\nerfstudio_setup.ps1 -VerifyOnly`
- **CUDA 컴파일 안내**: tiny-cuda-nn 설치와 splatfacto 첫 실행에는 MSVC 빌드 환경이 필요하다. `cl.exe`가 PATH에 없으면 스크립트가 경고를 출력한다. 이 경우:
  1) "x64 Native Tools Command Prompt for VS 2022"를 열어 그 안에서 `powershell` 실행 후 스크립트 실행, 또는
  2) cmd에서 `"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"` 실행 후 `powershell` 진입.
  (공식 문서: 설치와 첫 `splatfacto` 실행 사이에 터미널을 닫았다면 이 활성화를 다시 해야 한다.)

### 2.3 스크립트가 하는 일

1. 사전 요구 사항 확인(`nvidia-smi`, `git`, `conda`) — 없으면 중단
2. conda 환경 `nerfstudio`(python 3.10) 생성 → PyTorch 2.1.2+cu118 → conda cuda-toolkit 11.8 → tiny-cuda-nn(git) → `pip install nerfstudio`
3. COLMAP 확인(없으면 winget 검색 시도 + 공식 릴리스 zip 수동 설치 안내), FFmpeg 확인(없으면 `winget install Gyan.FFmpeg` 시도)
4. `ns-train --help` 정상 응답 확인
5. nerfstudio 공식 샘플 데이터 `poster` 다운로드(`ns-download-data nerfstudio --capture-name=poster`) 후
   `ns-train nerfacto` / `ns-train splatfacto` 각각 `--max-num-iterations 150` 단기 학습 → **둘 다 에러 없이 종료하면 "P0 종료 기준 3번 충족" 메시지와 함께 종료 코드 0**

## 3. 성공 판정 (무엇이 보이면 성공인가)

1. **설치 성공**: 스크립트 2~3단계에서 각 설치 항목 뒤 초록색 `[OK]` 출력.
2. **CLI 성공**: `ns-train --help` 뒤 `[OK] ns-train --help 정상`.
3. **학습 성공**: 각 `ns-train` 실행 시
   - 콘솔에 학습 설정 요약이 출력되고, 반복(iteration) 진행 로그가 순차적으로 찍힌 후,
   - `$MaxIterations`(기본 150) 도달 시 오류 없이 프로세스가 종료되고,
   - 로그에 `[OK] nerfacto 단기 학습(150 iter) 에러 없이 완료` / `[OK] splatfacto ...`가 뜬다.
4. **최종 판정**: 스크립트 마지막에
   ```
   >>> P0 종료 기준 3번 충족: splatfacto + nerfacto 모두 에러 없이 구동됨 <<<
   ```
   가 초록색으로 출력되고 종료 코드가 0(`$LASTEXITCODE -eq 0`)이면 **P0-L4의 CLI 검증 요건 충족**이다. 이 문구는 마일스톤 문서의 P0 종료 기준 3번("RTX 4070 데스크톱에서 `ns-train splatfacto` 및 `ns-train nerfacto` CLI가 에러 없이 구동됨")에 직접 대응한다.
5. **판정 범위 주의**: 위 1~4번 판정은 **P0 종료 기준 3번(`ns-train` CLI 구동)까지**를 커버한다. 마일스톤 P0-L4 DoD(166행)의 나머지 요건 — **`colmap` 설치**와 **샘플 데이터셋 내보내기(`ns-export gaussian-splat`) 동작 확인** — 는 스크립트가 자동으로 수행하지 않는다(스크립트 3단계는 COLMAP 확인·winget 검색·수동 설치 안내까지만 하고, `ns-export`는 주석 예시만 존재). 이 두 항목을 별도로 수행해야 P0-L4를 완료로 표시할 수 있다(`ns-export` 동작 확인은 §5.1의 명령으로).
6. **(선택) 뷰어 확인**: 학습 중 SSH 터널(7007)을 맥 브라우저에서 열면 뷰어가 보인다. 이는 판정 요건이 아니라 참고 확인이다.

> 스크립트 실행 검증 상태: 본 문서·스크립트는 macOS 작성 환경에서 문서화·명령 검증만 수행했고(명령·버전·문서 절차는 공식 문서/PyPI/GitHub API로 2026-10-25 확인), **Windows 실기에서의 스크립트 실행은 아직 수행되지 않았다.** 데스크톱에서 1회 실행해 3번 항목의 문구가 실제로 출력되는지 확인할 것.

## 4. 자주 나는 오류와 대처

| 증상 | 원인 | 대처 |
| --- | --- | --- |
| `No CUDA toolset found` (tiny-cuda-nn/gsplat 컴파일 단계) | MSVC 빌드 환경이 터미널에 활성화되지 않음 | `vcvars64.bat` 실행 후 같은 터미널에서 재시도(§2.2 참조). 그래도 안 되면 CUDA 설치 폴더의 `extras\visual_studio_integration\MSBuildExtensions` 파일들을 Visual Studio의 `BuildCustomizations` 폴더로 복사(공식 문서 명시된 절차) |
| tiny-cuda-nn 컴파일 중 MSVC 오류 | MSVC v143이 최신인 경우 실패 보고 있음(공식 문서) | Visual Studio Installer에서 **MSVC v142(14.29, VS 2019용) 추가 설치** 후 `vcvarsall.bat x64 -vcvars_ver=14.29`로 활성화 |
| `pip install torch...` 후 CUDA 미인식 / 버전 꼬임 | 시스템에 다른 버전 CUDA/PyTorch가 섞임 | **cu118 wheel(torch 2.1.2+cu118) + conda cuda-toolkit 11.8 조합만 유지**(공식 권장). 시스템 전역 CUDA 설치 버전과 혼동하지 말 것 — 컴파일용 툴킷은 conda 환경 안 것을 쓴다. 드라이버 CUDA 지원은 `nvidia-smi`로 확인(11.8 이상) |
| pip 충돌(torch/tinycudann 중복 버전) | 이전 설치 잔여 | 공식 문서 절차: `pip uninstall -y torch torchvision functorch tinycudann` 후 재설치. 스크립트는 설치 전 자동 실행함 |
| `ns-train splatfacto` 첫 실행이 수 분 멈춘 것처럼 보임 | gsplat CUDA 코드 **첫 실행 시 컴파일**(공식 문서) | 정상. 이때도 MSVC 환경 활성화가 필요. 두 번째 실행부터는 캐시됨 |
| `colmap -h` 실패 / `ns-process-data`에서 COLMAP 미발견 | PATH 미등록 또는 미설치 | 스크립트 3단계 안내대로 공식 릴리스 zip(`colmap-x64-windows-cuda.zip`) 설치 후 PATH 등록, 터미널 재시작 |
| `ns-download-data` 다운로드 실패 | 공개 데이터 서버 간헐 오류 | 명령 재실행. 반복 실패 시 네트워크/방화벽 확인 |
| conda activate 안 됨 (PowerShell) | `conda init powershell` 미실행 | Miniconda 설치 후 1회 `conda init powershell`, 터미널 재시작 |
| 학습은 되는데 뷰어가 안 열림 | 뷰어 websocket 포트(기본 7007) 미포워딩 | `ssh -L 7007:localhost:7007 ...` 터널로 접속(공식 문서: 원격 시 포트 포워딩 필요) |
| 스크립트가 `NativeCommandError`를 내며 갑자기 중단(Windows PowerShell 5.1) | **미검증 추정(2026-10-25 — Windows 실기 실행 전)**: `$ErrorActionPreference='Stop'` 상태에서 네이티브 명령의 stderr 리다이렉트(`2>$null`, `*>$null` — 스크립트 내 전 리다이렉트 지점)가 PS 5.1에서는 오류 레코드로 취급되어 예외가 될 수 있다. pip처럼 stderr에 경고를 자주 쓰는 명령에서 발생 가능 | PowerShell 7(`pwsh`)로 실행한다. 또는 발생 확인 시 해당 리다이렉트 구간에서만 `$ErrorActionPreference = 'Continue'`로 바꿨다 복원한다. 첫 실행 시 리다이렉트 지점에서 중단되지 않는지 주의 깊게 관찰할 것 |

참고: nerfstudio 공식 문서는 Windows 설치를 "less tested and more fragile"로 명시하고, 대안으로 Linux/WSL2를 제시한다. 본 프로젝트(D3)는 Windows 데스크톱이 확정이므로 우선 네이티브로 진행하고, 진행 불가 시 그 사실과 함께 대안(WSL2)을 디스커션에 올려 결정한다.

## 5. 학습 산출물(.ply)을 맥으로 옮기기

### 5.1 내보내기 (데스크톱)

splatfacto 학습이 끝나면 config.yml 경로(형식: `outputs/<데이터셋>/<method>/<날짜시간>/config.yml`)를 확인하고:

```powershell
ns-export gaussian-splat --load-config outputs\product01\splatfacto\<날짜시간>\config.yml --output-dir exports\splat
# → exports\splat\splat.ply 생성 (공식 문서: splatfacto 학습 결과만 .ply 내보내기 가능 — nerfacto 모델에서는 불가)
```

`ns-export gaussian-splat --load-config <config> --output-dir exports/splat` 명령은 nerfstudio 공식 splatfacto 문서에 명시된 형식이다.

### 5.2 전송 (맥에서 실행)

**방법 A — SCP (권장, SSH 구성과 세트)**

```bash
# 맥 터미널에서. Windows OpenSSH 경로는 슬래시(/) 표기를 쓴다.
scp '<윈도우계정>@<데스크톱IP>:C:/Users/<계정>/nerfstudio-work/exports/splat/splat.ply' ./capture/
```

여러 파일·폴더째로는 `scp -r` 사용. 프로젝트 규칙(마일스톤 P0-L5)에 따라 `*.ply`는 Git LFS 추적 대상이므로 커밋 전 `.gitattributes` 등록 상태를 확인할 것.

**방법 B — SMB 공유 폴더**

1. 데스크톱: 전송용 폴더(예: `C:\transfer`) 우클릭 → 속성 → 공유 → 계정 지정 공유.
2. 맥: Finder → ⌘K → `smb://<데스크톱IP>` → 계정/암호 입력 → 복사.
3. 대용량 .ply(수백 MB~GB) 안정 전송에 유리. 공유 폴더는 방화벽(File and Printer Sharing) 허용 필요.

> 둘 중 하나만 운영해도 충분하다. SSH 구성 시 A를 기본으로 쓰고, 창을 띄워 드래그로 옮기고 싶을 때 B를 쓴다.

### 5.3 이후 흐름 (요약 — 상세는 구현 문서 3장)

맥에서 SuperSplat으로 정제 → **표준 Binary `.ply`로 내보내기**(최신 SuperSplat 기본 SPZ 내보내기는 플러그인 파서와 호환되지 않음 — `docs/p0/Unity_셋업_체크리스트.md` §11 참조) → Unity에서 `Tools → Gaussian Splats → Create GaussianSplatAsset`으로 `.asset` 변환.
