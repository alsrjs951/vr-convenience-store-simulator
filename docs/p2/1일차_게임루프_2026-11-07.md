# 1일차 게임 루프 구현·시뮬레이터 검증 (2026-11-07)

마일스톤 M2의 게임 로직 부분이다. 튜토리얼 6단계 → 손님 5명 계산 → 정산까지 한 판이 이어진다.

## 무엇이 확인됐고 무엇이 안 됐나

| 구분 | 상태 |
|---|---|
| **실험 성공** | XR Device Simulator 입력만으로 1일차 전체 자동 플레이 통과. 에디터 129/129, IL2CPP 플레이어 3회 각 129/129, 실제 마우스 입력 0, 예외 0. OpenXR Mock 런타임으로 HMD가 있을 때 시뮬레이터가 꺼지는 것 확인 |
| **실제 품질** | 미평가. 사람이 해 본 적이 없다. 난이도·재미·안내 문구의 이해도는 모른다. S등급 98점은 자동 플레이 값이라 난이도 근거가 아니다 |
| **HMD 검증** | **안 함.** Quest 2 미연결이고 Mock 런타임은 실기가 아니다. 머리·손 추적, 손 닿는 거리, 글자 가독성, 멀미, 컨트롤러 조작감은 모두 미확인 |

## 구현한 내용

**흐름:** 출근 안내 → 튜토리얼(잡기·돌리기·스캔·봉투·카드·현금) → 손님 5명(10초 간격, 150초 제한, 1일차는 초과해도 경고음만) → 정산 보드.

**규칙:**

- **스캔:** 바코드 면이 스캐너 판을 향할 때(±50°)만 찍힌다. 몸통이나 세워서 댄 상품은 찍히지 않는다. 비스듬히 닿은 뒤 눕히면 찍힌다.
- **취소:** 주문보다 많이 찍으면 결제가 막히고 POS의 [-]를 광선과 트리거로 눌러 취소한다. 취소마다 정확도 10% 감점.
- **봉투:** 스캔한 상품만 담긴다. 봉투가 필요 없는 주문은 스캔만 끝나면 결제할 수 있다.
- **카드:** 스캔과 봉투 담기 전에는 거부되고 카드는 손에 남는다. (11/07 저녁 변경) Quest 2 리허설에서 "어느 방향으로 어떻게 꽂는지 모르겠다"는 소감이 나와, 단말기 앞면에 노란 테두리 슬롯을 내고 카드를 들면 꽂을 자리에 흐린 카드가 보이게 했다. 슬롯 가까이 가져가면 바른 자세로 빨려 들어가고, 놓아도 꽂힌 채 남는다. 자세한 내용은 `Quest2_실기점검_2026-11-07.md`의 "카드 단말기 수정"에 있다.
- **현금:** 손님 지폐를 서랍에 넣고 거스름돈을 접시에 놓는다. 스캔 전이면 지폐가 접시로 돌아간다. 놓는 도중에는 진행 금액만 표시한다. 금액이 넘치면 0.5초 뒤, 모자란 채 멈추면 8초 뒤 오류로 친다.
- **낙하:** 상품은 바닥에 닿고 3초 뒤, 카드·화폐는 즉시 제자리로 돌아온다.
- **정산:** 기획서 11장의 1일차 공식 `50×매출 달성률 + 30×(1−이탈/손님) + 20×정확도`. S≥90, A≥75, B≥60.

## 실행 방법

```powershell
Builds\Store\VRStore.exe
```

에디터에서는 `Assets/Scenes/StoreScene.unity`를 열어 Play한다. 씬을 다시 만들려면 메뉴 `Tools > P2 > Build Store Scene`.

**시뮬레이터 조작:** 왼쪽 안내판이 POS를 가리므로 오른쪽 위 `−`로 접는다.

| 입력 | 동작 |
|---|---|
| 마우스 | 시작 상태에서는 시선 |
| `Y` | 오른손 조작 켜기 |
| `R` | 마우스를 이동↔회전으로 전환 (`Y` 직후는 회전이므로 한 번 눌러 이동으로) |
| 마우스, `Z`+마우스 | 손 이동, 깊이 이동 |
| 왼쪽 `Ctrl`+마우스, `Ctrl`+`Z`+마우스 | 손 회전, 롤 |
| `G` | 그립(누르는 동안 쥠) |
| 마우스 왼쪽 버튼 | 트리거(POS 버튼) |

자동 검증:

```powershell
Unity.exe -projectPath <프로젝트> -executeMethod P2StoreBuilder.VerifyEditor -p2-verify -logFile verify.log
Builds\Store\VRStore.exe -p2-verify -p2-evidence <출력폴더> -screen-width 1920 -screen-height 1080 -screen-fullscreen 0 -logFile player.log
```

검증 중에는 마우스를 움직이지 않는다. 실제 마우스도 시뮬레이터에 입력되기 때문이다(보고서 `externalMouseMotion`에 기록).

## HMD가 있으면 시뮬레이터 자동으로 끄기

XR Device Simulator는 켜져 있으면 진짜 HMD 장치를 Input System에서 지운다(`SimulatedDeviceLifecycleManager.OnEnable`). 그대로 Quest를 연결하면 머리 추적이 멈춘다. 그래서 시뮬레이터 프리팹에 `SimulatorHmdGuard`를 붙였다. XR 런타임이 올라와 있으면 시뮬레이터의 어떤 구성 요소보다 먼저 시뮬레이터 전체를 끈다. 모든 씬이 같은 프리팹을 쓰므로 P0, P1 씬에도 적용된다. HMD가 없으면 예전처럼 시뮬레이터로 동작한다.

Quest 없이 시험하려고 Unity OpenXR 패키지의 **Mock 런타임**을 `XR_RUNTIME_JSON`으로 지정해 실제 OpenXR 경로를 띄웠다.

| 조건 | 시뮬레이터 | Input System의 HMD |
|---|---|---|
| Mock 런타임, 가드 없음(에디터, 수정 전 기준) | 켜짐 | `XRSimulatedHMD`만. 진짜 HMD가 지워짐(문제 재현) |
| Mock 런타임, 가드 있음, 에디터 | 꺼짐 | `OpenXRHmd`, Touch 컨트롤러 2개 |
| Mock 런타임, 가드 있음, IL2CPP 플레이어 | 꺼짐 | `OpenXRHmd`, Touch 컨트롤러 2개 |
| 런타임 없음, 에디터·플레이어 | 켜짐 | `XRSimulatedHMD` (1일차 검증이 이 경로) |

증거: `docs/p2/evidence/hmd_guard/*.json`. 다시 시험하려면:

```powershell
$env:XR_RUNTIME_JSON = "<프로젝트>\Library\PackageCache\com.unity.xr.openxr@b5b77b4027be\Runtime\MockRuntime\unity-mock-runtime.json"
Builds\Store\VRStore.exe -hmd-guard-check -hmd-guard-evidence <출력.json> -logFile player.log
Remove-Item Env:\XR_RUNTIME_JSON
```

**Quest 시험 전에 알아 둘 것:**

- **이 PC에는 활성 OpenXR 런타임이 없다**(레지스트리 키, Oculus 기본 경로, `OVRService` 모두 없음). Meta Quest Link를 설치하고 활성 OpenXR 런타임으로 지정해야 한다.
- Mock은 장치와 세션의 흐름만 흉내 낸다. 실제 머리·손 포즈, 트리거·그립 입력, Link 환경의 렌더링은 시험하지 못했다.
- **미확인:** 런타임은 설치됐는데 헤드셋이 꺼져 있을 때. OpenXR 로더가 실패하면 시뮬레이터로 동작하지만, 로더가 뜨면 시뮬레이터가 꺼져 조작할 수 없다. 이때는 헤드셋을 연결하고 다시 실행한다.
- 실행 중에 헤드셋을 연결하는 것은 지원하지 않는다. 다시 실행해야 한다.
- `Builds/P1Interaction`은 가드를 넣기 전 빌드다. 실기에서 쓰려면 다시 빌드한다.
- XRI 샘플을 다시 가져오면 프리팹의 가드가 사라진다. 메뉴 `Tools > P2 > Install Simulator HMD Guard`로 다시 붙인다.

## 미완료·미검증

**코드는 있으나 이번 자동 검증이 지나가지 않은 경로:**

- 튜토리얼 시간 경과 힌트(15초, 20초)와 현금 2회 오류 힌트, 3회 오류 자동 완료
- 150초 초과 경고음
- 주문에 없는 상품이 찍힌 경우(1일차는 그 주문의 상품만 존재해 발생하지 않음)
- 비스듬히 닿은 뒤 눕혀서 찍기

**알려진 제한:**

- 소리는 재생만 될 뿐 들어서 확인하지 않았다.
- 세운 상품은 옆 상품에 부딪히면 넘어진다. 넘어져도 집을 수 있다.
- 봉투에 담은 상품은 충돌체가 꺼지므로 서로 겹쳐 보인다.
- 서랍과 단말기는 중앙에서 약 0.8m 떨어져 있다. 실기에서는 옆으로 한두 걸음 옮겨야 할 수 있다.
- 3일차, 특수 요청, 전체 매장 배치는 아직 없다. 2일차(입고·진열·폐기)는 2026-11-08에 시뮬레이터로 구현했다(`2일차_2026-11-08.md`). 1일차 정산판 아래 "2일차 시작" 버튼으로 이어진다.
- 상품 3DGS 품질과 Unity 시점 바코드 판독은 추후 과제 그대로다. 스캔은 이미지 판독이 아니라 충돌 규칙이다.
- 빌드 크기 1.7GB. 12종을 모두 포함한다.

## 작업 중 발견해 고친 것

- **상품 7종의 표시 이름 깨짐.** 치토스·콘칩·꼬깔콘·꼬북칩·오감자·오징어땅콩·썬칩의 이름이 12종 복원 일괄 작업에서 잘못 인코딩돼 매니페스트와 SO에 들어가 있었다. P1 검증은 이름을 화면에 표시하지 않아 잡지 못했다. 복구했고, 이름 검사(`setup.product_names_readable`)를 추가했다.
- **거스름돈 거짓 오류 가능성.** 한 장씩 놓는 정상 동작도 중간 금액이 0.5초 유지되면 오류로 세는 구조였다. 지금은 위 규칙대로 바꿨고 거짓 오류 0회를 검사한다.
- **세워서 대도 찍힐 수 있는 판정.** 바코드 판정 볼륨의 아래 모서리가 구역에 닿으면 찍혔다. 각도 규칙을 추가했다(P1 씬은 기본값 0이라 영향 없음).
- **가드의 두 가지 초기 오류.** 코드만 보면 맞아 보였지만 Mock 시험에서 드러났다. 첫째, `XRSettings.isDeviceActive`는 `Awake` 시점에 런타임이 있어도 거짓이라 가드가 작동하지 않았다. 지금은 `activeLoader`를 본다. 둘째, 가드가 시뮬레이터 본체보다만 앞서고 장치 관리자(실행 순서 -29995)보다는 뒤여서, 에디터에서는 멀쩡한데 플레이어에서만 HMD가 사라졌다. 지금은 장치 관리자보다 앞선다.
- **거스름돈 시험의 간헐 실패(플레이어 4회 중 1회).** 게임 규칙이 아니라 검증기 문제로 판단했다. 이 시험만 손이 움직이는 도중에 놓았고, XRI는 직전 손 움직임으로 물체를 던지므로 가벼운 지폐가 계산대 뒤로 떨어졌다가 제자리로 돌아간 것으로 보인다. 실패 당시 화면에 접시 위 지폐가 없었고, 도착 순간 속도가 최대 0.84m/s로 측정됐다. 지폐가 날아가는 순간을 직접 잡지는 못했다. 지금은 멈춘 뒤 놓고(놓는 순간 0.000m/s) 이를 `input.set_downs_were_still`로 검사하며, 수정 후 4회 모두 통과했다. 사람이 던져도 제자리로 돌아오므로 진행이 막히지는 않는다.
