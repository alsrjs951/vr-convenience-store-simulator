# 다수 상품 부하 측정과 컬링 시험 (2026-11-07)

2일차 진열대를 만들기 전에, 상품을 여러 개 띄웠을 때 프레임이 버티는지 재고 보이지 않는 상품을 건너뛰는 컬링을 시험한 결과다. 설계 판단용 추세 측정이다.

> **이 문서의 초판 수치는 틀렸다.** 상품 위치 지정이 일부 무시된 채 측정했다(아래 "측정 중 드러난 함정"). 지금 수치가 다시 잰 값이다. 결론의 방향은 같지만 등 뒤 비용이 90%에서 82%로, 3.5m 24개가 기준 통과에서 초과로 바뀌었다.

## 이 수치의 성격

| 구분 | 내용 |
|---|---|
| **실제로 잰 것** | RTX 4070, IL2CPP 빌드, OpenXR **Mock 런타임** 스테레오(Multi-pass), 눈당 1780×1978(Quest 2 패널 1832×1920과 픽셀 수 동일), 눈높이 1.36m, VSync 끔 |
| **판정이 아니다** | Quest 2가 아니다. Link 인코딩과 컴포지터 부하, 실제 머리 움직임이 빠져 있어 **실기는 이보다 나쁘다.** 얼마나 나쁜지는 모른다 |
| **규약과의 차이** | 구현 문서 7.1의 60초×3회가 아니라 장면당 6초×2회다. `perf_log.csv`의 `device`는 `editor`와 `quest2-link`뿐이라 **이 값은 그 파일에 넣지 않았다** |
| **상품** | 현재 12종을 그대로 쓴 개별 렌더러. 병합본과 경량본(LOD1)은 아직 없어 시험하지 못했다 |

재현성은 좋다. 두 번의 측정이 전 장면에서 0.15ms 안쪽으로 일치했다. 전 장면 스크린샷을 한 장에 모아 눈으로 확인했다(`evidence/load/sheet_*.jpg`). 측정기는 상품 위치와 눈높이가 어긋나면 스스로 멈춘다.

## 핵심 결과

**1. 비용은 Gaussian 수에 비례한다.** 100만 개당 스테레오 약 6~7ms(3.5m 5.8, 1m 6.3, 30cm 7.1), 데스크톱 단안 약 3ms다.

**2. 렌더러 그대로면 보이지 않아도 비용을 낸다.** 카메라 뒤 상품의 비용이 눈앞 1m의 82%다. 업스트림에는 물체 단위 시야 컬링이 없다.

**3. 시야 컬링을 넣으면 그 비용이 사라진다.** 아래 "컬링 시험"을 보라. 사방에 상품이 둘러선 배치에서 GPU 시간이 절반이 됐고, 화면은 그대로이며, 회전 중 끊김도 늘지 않았다.

**4. 문서 G1-H 구도는 여유가 크다.** 1m 앞 3개 + 30cm 앞 2개가 GPU 3.83ms, 프레임 p95 4.41ms다.

**5. 1일차는 여유가 있다.** 상품 렌더러가 최대 2개라 GPU 약 3ms 이하다. 실기 확인 전까지는 Mock 기준이다.

## 측정표 (Mock 스테레오, 2회 평균, 컬링 끔)

기준: 프레임 p95 ≤ 13.5ms(구현 문서 7.1). Link 부하가 없는 값이므로 통과해도 실기 통과를 뜻하지 않는다. 단위는 ms이고 `GPU / p95`다.

| 1 | 13만 | 0.99 / 1.82 | 1.42 / 2.18 | 0.98 / 1.80 | |
| 2 | 23만 | 1.58 / 2.38 | 2.66 / 3.26 | 1.55 / 2.37 | |
| 4 | 40만 | 2.64 / 3.22 | 4.45 / 4.98 | 2.59 / 3.20 | |
| 8 | 72만 | 4.79 / 5.38 | 6.18 / 6.72 | 4.54 / 5.11 | 3.95 / 4.55 |
| 12 | 112만 | 7.29 / 7.62 | 9.78 / 10.05 | 6.80 / 7.09 | |
| 16 | 153만 | 9.73 / 10.06 | 11.77 / 12.08 | 9.03 / 9.32 | |
| 24 | 225만 | 14.29 / **14.51** | 16.85 / **17.18** | 13.33 / **13.67** | 11.67 / 11.96 |

상품 없는 장면은 GPU 0.38 / p95 1.48이다. 굵은 값이 기준 초과다.

- **기준 통과:** 16개(153만)까지 모든 거리에서 통과했다. 24개(225만)는 모든 거리에서 넘는다.
- **문서 예산과의 관계:** 150만(최적화 목표)에 가까운 16개는 13.5ms까지 Link 부하 몫이 p95 기준 1.4~4.2ms 남는다. 200만(게이트 기준)은 직접 재지 않았지만 24개 결과로 보면 근접 시 여유가 거의 없을 것이다.

### 완화책 비교 (GPU ms, 2회 평균)

| 조건 | 30cm, 8개 | 1m, 24개 |
|---|---:|---:|
| 기본 | 6.18 | 14.29 |
| 렌더 스케일 0.85 | 5.35 (-13%) | 12.96 (-9%) |
| 렌더 스케일 0.7 | 4.60 (-26%) | 12.57 (-12%) |
| 정렬 4프레임마다 (`m_SortNthFrame=4`) | 5.34 (-14%) | 11.78 (-18%) |
| SH 차수 0 (`m_SHOrder=0`) | 6.00 (-3%) | 13.65 (-4%) |

- **렌더 스케일**은 화면을 덮는 근접 장면에서 더 듣는다. 다만 Gaussian이 많으면 픽셀을 줄여도 크게 내려가지 않는다.
- **정렬 주기**는 14~18% 줄인다. 머리를 움직일 때 겹침 순서가 어긋나는지는 **확인하지 못했다.** 실기에서 봐야 한다.
- **SH 차수**는 거의 줄이지 못한다. 런타임 설정만 시험했으므로, 에셋 자체를 `VeryLow`로 만들 때의 메모리 절감은 별개다.

### 그 밖의 값

| 항목 | 값 |
|---|---|
| 렌더러당 그래픽 메모리 | 약 62MiB (24개에 1.7GiB). 인스턴스마다 버퍼를 따로 만든다 |
| VRAM | 유휴 1.8GB → 최대 3.2GB (12GB 중). 문제없음 |
| CPU (24개, 1m) | 메인 2.6ms, 렌더 스레드 4.1ms. 렌더 스레드가 렌더러당 약 0.15ms 늘어난다 |
| 상품 생성 순간 | 호출 5~6ms, 그 프레임 최대 14~18ms(72Hz 예산 13.9ms를 넘을 수 있음) |

## 컬링 시험

Gaussian 패키지를 프로젝트에 내장해(`Packages/org.nesnausk.gaussian-splatting`, 업스트림 v1.1.0, MIT) 렌더러 하나를 고쳤다. **머리 정면 기준 원뿔(75°) 밖의 렌더러는 정렬과 그리기를 건너뛴다.** 렌더러를 끄면 GPU 버퍼를 지웠다가 다시 만들어 멈칫하지만, 이 방식은 버퍼를 그대로 두고 건너뛰기만 한다. 정확한 시야 절두체 대신 넓은 원뿔을 쓰는 이유는 헤드셋마다 다른 시야에 의존하지 않기 위해서다.

**기본값은 꺼짐이다.** 게임에는 아직 켜지 않았으니 지금 동작은 바뀌지 않는다. `GaussianSplatRenderer.ViewCullHalfAngleDegrees`로 켠다.

### 효과 (Mock 스테레오, 24개, 225만, 2회 평균)

| 배치 | 끔 GPU / p95 | 켬 GPU / p95 | 건너뛴 렌더러 |
|---|---:|---:|---:|
| 사방 고리(1.5m) | 12.13 / 12.37 | **6.11 / 6.73** | 13개 |
| 고리, 초당 90° 회전 | 12.16 / 12.45 | **6.14 / 6.79** | 평균 12.8개 |
| 정면 1m (전부 시야 안) | 14.19 / 14.33 | 14.19 / 14.35 | 0개 |
| 전부 등 뒤 | 11.57 / 11.85 | **0.38 / 1.58** | 24개 |

- **사방에 있으면 절반이 된다.** 상품 수가 2배여도 비슷한 프레임이 나온다는 뜻이다. 등 뒤에만 있으면 상품이 없는 장면(0.40)과 같다.
- **눈앞의 상품 비용은 줄지 않는다.** 정면 1m는 그대로다. 그래서 "바라보는 쪽 상품 합계"의 예산은 여전히 필요하다.
- **판정 비용은 보이지 않는다.** 정면 1m에서 켜고 끈 값이 같다.
- CPU도 준다. 고리 배치에서 렌더 스레드 3.3ms → 2.0ms, 메인 1.9ms → 1.4ms.

### 끊김과 화면 변화

| 확인 | 결과 |
|---|---|
| 회전 중 최대 프레임 시간 | 켬 14.44 / 13.04ms, 끔 22.12 / 20.67ms. 다시 보일 때 튀지 않는다 |
| 같은 자세 8곳, 켜고 끈 화면 비교(Mock) | 16장 중 차이 최대 1단계, 4픽셀. 2회차는 0픽셀 |
| 같은 비교(데스크톱) | 차이 최대 3단계, 자세당 최대 648픽셀. 8단계를 넘는 픽셀 0 |

자세끼리는 화면이 크게 달라(16.7만 픽셀) 비교 자체는 유효하다.

### 컬링의 조건과 미확인

- **원뿔은 헤드셋 시야보다 넓어야 한다.** Mock의 가장 먼 모서리는 정면에서 64.5°로 75°보다 10.5° 안쪽이다. **Quest 2 실제 값은 모른다.** 연결하면 `-p2-load` 로그의 `widest view`로 바로 확인한다. 75°보다 가까우면 원뿔을 넓힌다.
- 실기에서 빠르게 머리를 돌릴 때 가장자리에서 상품이 튀어나오는지는 HMD로만 볼 수 있다.
- 복원 잔상이 큰 상품은 경계 구가 커져 덜 건너뛴다. 안전한 쪽의 오차다.
- 정렬 주기를 늘린 렌더러가 다시 보일 때 바로 정렬하도록 해 두었지만, 그 조합은 측정하지 않았다.

### 되돌리기

`Packages/org.nesnausk.gaussian-splatting` 폴더를 지우고 `Packages/packages-lock.json`을 되돌리면 된다. `manifest.json`은 바꾸지 않았다. 다만 측정기(`P2LoadTest.cs`)가 패치된 API를 쓰므로 측정기도 함께 지워야 한다. 업스트림과 다른 곳은 `Runtime/GaussianSplatRenderer.cs` 한 파일이고, `Project patch`로 표시해 두었다.

## 2일차 설계에 주는 영향

1. **컬링을 켜고 "바라보는 쪽 Gaussian 합계 150만 이하"로 잡는다.** 구현 문서 7.2의 "가시 합계 150만"이 컬링을 켜야 비로소 맞는 말이 된다. 컬링이 없으면 등 뒤까지 모두 합쳐 150만이라, 원본 기준 매장 전체에 상품 16개 정도가 한도다.
2. **경량본(LOD1)은 여전히 필요하다.** 바라보는 진열대 한 면에 상품이 많이 몰리면 컬링으로 줄지 않는다. 비용이 Gaussian 수에 비례하므로 병합만으로는 GPU 시간이 크게 줄지 않을 것으로 본다(병합은 렌더 스레드 비용과 깊이 역전을 해결한다). 병합 효과는 아직 재지 못했다.
3. **멀리 있는 진열대는 정렬 주기를 늘리는 것을 후보로 둔다.** 약 15% 절감이고 에셋 작업이 필요 없다. 시각 영향은 실기 확인이 필요하다.
4. **상품은 미리 만들어 둔다(풀).** 지금은 손님이 올 때 생성해 프레임이 튈 수 있다. 구현 문서 5.7의 풀 계획과 같은 방향이다.

## 측정 중 드러난 함정

최종 수치 전에 측정을 여러 번 **폐기했다.** 대부분 숫자만 보면 그럴듯했다.

| 문제 | 어떻게 찾았나 | 조치 |
|---|---|---|
| URP가 매 프레임 눈 텍스처 스케일을 덮어써 해상도가 적용되지 않음(1512×1680) | 로그 | URP 렌더 스케일로 맞춤 |
| Mock 머리 높이가 0.1m라 상품이 계산대에 가려짐. XR Origin을 올려도 리그의 중력이 되돌림 | 스크린샷 | 카메라 오프셋으로 눈높이 유지 |
| 머리 높이가 안정되기 전에 한 번만 맞춰 눈높이가 어긋남 | 측정기 자체 검사가 측정을 중단 | 매 프레임 유지, 어긋나면 측정 중단 |
| 상품 프리팹의 Rigidbody 보간이 측정기가 지정한 위치를 덮어써 일부가 이전 자리에 남음. **이 값으로 초판 문서와 빌드 기록을 썼다** | 컬링 결과의 모순(켠 뒤 눈앞 상품이 건너뛰어짐) | 측정 중 보간 끔, 위치가 어긋나면 측정 중단 |

## 재현 방법

```powershell
# 데스크톱. 컬링 시험만 하려면 -p2-load-culling을 더한다.

# Mock 스테레오
$env:XR_RUNTIME_JSON = "<프로젝트>\Library\PackageCache\com.unity.xr.openxr@b5b77b4027be\Runtime\MockRuntime\unity-mock-runtime.json"
Builds\Store\VRStore.exe -p2-load -p2-load-output <폴더\결과.csv> -screen-width 1920 -screen-height 1080 -screen-fullscreen 0 -logFile load.log

```

출력 폴더를 미리 만들어야 스크린샷이 남는다. 마우스를 움직이지 말고 GPU를 쓰는 다른 프로그램을 끈다. 코드는 `Assets/Scripts/Diagnostics/P2LoadTest.cs`이고 `-p2-load`일 때만 동작한다.

증거: `docs/p2/evidence/load/`(원본 CSV 6개, 전 장면 모음 `sheet_*.jpg`, 켜고 끈 화면 한 쌍, 회귀 보고서).
