# 시작 화면과 코어 루프 개선 (2026-11-09)

> **상태: 코드와 씬 재빌드까지 끝났다.** 검증 범위는 "5. 검증"에 적었다. Quest 2로는 아직 보지 않았다. 수치는 전부 [제안]이고 11/15 플레이테스트로 조정한다.

## 1. 왜 바꿨나

사용자 요청으로 시작 화면과 코어 루프를 기획 관점에서 점검했다. 코드와 11/07 Quest 1일차 플레이 기록에서 나온 문제는 다음과 같다.

| 문제 | 근거 |
|---|---|
| 시작 화면이 없다. 실행 3초 뒤 튜토리얼이 시작되고, 3일차 뒤에는 게임을 다시 실행해야 한다 | `GameManager.Start`, `IntroSeconds`, `ShowFinalReport` 뒤 `yield break` |
| 이동을 가르치는 단계가 없어 2일차에 박스를 든 채 처음 걷게 된다 | 튜토리얼 6단계, 입고 안내 I1 |
| 잘해도 못해도 결과가 같다. 첫 Quest 플레이가 S 100점이었다 | 점수식에 시간이 없음 |
| 제한시간 여유가 커서 손님을 세워 두고 진열하는 쪽이 유리하다 | 첫 플레이 손님당 많아야 약 55초(전체 328초 기준 추정), 2일차 제한 120초 |
| 줄에서는 시간이 안 흘러 피크에도 손님이 쌓이지 않는다 | `RunOrder`의 `remaining`, `RunDay`의 순차 호출 |
| 계산대를 떠나면 남은 시간을 볼 수 없다 | 주문 HUD는 계산대에만 있음 |
| 결제가 끝나도 보상이 없다 | 감사 음성 없음, 매출은 정산 때만 표시 |

## 2. 만든 것

### 2.1 시작 화면 흐름 (`TitleFlow`, `GameManager`)

`타이틀 → 문 열림 → 걸어서 입장 → 출근 카드 → 일차들 → 퇴근 카드 → 결말 → 타이틀`

- **타이틀**: 닫힌 출입문에 패널을 붙였다. 출근하기(1일차), 2일차부터, 3일차부터, 이동 속도, 화면 가장자리, 시점 다시 맞추기. 레이와 트리거로 누른다. 누르기 전에는 튜토리얼도 손님도 시작되지 않는다.
- **시점**: 시작 뒤 플레이어를 문 앞에 세운다. 머리가 1m 넘게 벗어난 채 1.5초가 지나면 다시 맞춘다(헤드셋을 늦게 쓴 경우).
- **입장**: 문이 옆 벽으로 밀려 들어가고 도어벨과 점장 인사가 나온다. 바닥의 노란 화살표를 따라 계산대 안쪽 초록 네모까지 걷는다. 20초 뒤 조작 안내, 75초 뒤 계산대로 옮겨 준다.
- **출근·퇴근 카드**: 결제 카드와 같은 슬롯·안내를 쓴다. 20초 뒤 쉬운 안내, 70초 뒤 통과.
- **결말**: 평균 점수의 등급에 따라 보드 문구와 점장 음성이 달라진다. "처음으로"를 누르면 기록을 비우고 타이틀로 돌아간다.
- **자동 검사와 개발 옵션**: `-start-day`, `-skip-title`, 기존 검사 인자(`-p2-verify` 등), `-hmd-perf`가 있으면 타이틀 없이 예전처럼 시작한다. 문과 화살표는 씬에 꺼진 채로 있고 NavMesh 굽기 뒤에 만들어, 손님 경로와 기존 검사에 영향을 주지 않는다.

### 2.2 코어 루프 (`CustomerDirector`, `GameManager`, `WristWatch`)

| 항목 | 규칙 | 값 [제안] |
|---|---|---|
| 손님 만족도 | 남은 시간 비율 r로 계산. r ≥ 절반이면 1, 그 아래는 0.4까지 비례 감소, 이탈 0 | 절반, 0.4 |
| 팁 | r ≥ 절반이면 주문 금액의 10%를 100원 단위 반올림, 최소 100원 | 10% |
| 2·3일차 점수 | `40 × 매출 달성률 + 25 × 평균 만족도 + 15 × 정확도 + 20 × 과제 완료율`. 계산대까지 오지 못한 손님은 0 | - |
| 1일차 점수 | 예전 그대로(처벌 없음). 팁만 받는다 | - |
| 줄 대기 벌칙 | 2·3일차, 줄에 선 시각부터 호출까지 기다린 시간이 45초를 넘으면 초과분의 절반만큼 제한시간 감소. 주문 카드에 "오래 기다렸어요" | 45초, 0.5배, 최대 40% |
| 손목시계 | 왼손 손등, 근무 중에만. 일차, 대기 인원, 손님 번호, 남은 시간과 막대(절반 표시), 이탈 수, 오늘 번 돈. 손님 도착·재촉 때 깜빡임과 왼손 진동 | 13×6.4cm |
| 결과 카드 | 계산대 위 1.8초. "+3,300원 · 팁 300원", 이탈 시 "손님이 떠났습니다 · 이탈 1/3" | - |
| 감사 음성 | 보통 "감사합니다.", 팁을 줄 때 "와, 빠르시네요. 감사합니다." + 팁 효과음 | - |
| 주문 카드 | 시간 막대에 절반 표시 | - |

재촉 음성이 절반에서 나오므로 "재촉받기 전에 끝내면 팁"이라는 하나의 규칙으로 읽힌다.

## 3. 소리

`scripts/windows/make_game_voices.ps1`과 `make_game_sounds.py`에 12개를 더했다(감사 2종 남녀, 점장 3, 결말 4, 팁 효과음). 스크립트를 다시 돌린 결과 기존 파일 48개는 바이트까지 같아서 새 파일만 복사했다. TTS 배포 조건은 여전히 미확인이다.

## 4. 코드 지도

- 흐름: `Assets/Scripts/Gameplay/TitleFlow.cs`, `GameManager.RunTitle`·`RunEnding`·`ResetRun`·`PrepareStore`
- 규칙: `CustomerDirector.SatisfactionFor`·`TipFor`·`LinePenalty`, 값은 같은 파일 맨 위 상수
- 손목시계: `Assets/Scripts/Gameplay/WristWatch.cs`, 위치는 `P2StoreBuilder.BuildWristWatch`
- 문·화살표·안내판 위치: `P2StoreBuilder.BuildTitle`
- 검사: `Assets/Scripts/Diagnostics/P2TitleVerification.cs`

```text
Unity.exe -projectPath <프로젝트> -executeMethod P2StoreBuilder.VerifyEditor -p2-title-verify -p2-evidence <출력폴더> -logFile title.log
```

헤드셋 런타임이 잡히지 않도록 환경 변수 `XR_RUNTIME_JSON`을 없는 파일로 지정하고 돌린다.

## 5. 검증

모두 2026-11-09, 에디터 + XR Device Simulator + 가상 키보드·마우스, 외부 마우스 입력 0이다. 재미와 착용감은 이 검사로 알 수 없다.

| 항목 | 결과 |
|---|---|
| 컴파일, 씬 재빌드(`P2StoreBuilder.Build`) | 통과 |
| 시작 화면 흐름 `-p2-title-verify` | 66/66. 타이틀·시점·옵션은 레이와 트리거로, 입장은 왼손 스틱으로, 출근·퇴근 카드는 손으로 했다. 짧게 끝내려고 1일차만 튜토리얼 없이 돌렸고 손님 결제는 직접 호출했다. 75초·70초 구조, 처음으로 돌아가기, 2일차부터 시작 포함 |
| 1일차 + 다음 날 버튼 `-p2-verify -p2-next-day` | 201/201, S 98점(취소 1번) |
| 2일차 `-p2-day2-verify -start-day 2` | 291/291, A 89.6점. 일부러 놓친 손님 뒤의 3·4번째 손님이 줄에서 161·188초를 기다려 제한시간이 72초로 줄었다 |
| 2일차 아무것도 안 하기 `-p2-day2-idle` | 19/19, C 15점. 손님 3명의 대기 시간이 120·81·72초로 줄 벌칙대로 짧아졌다 |
| 화면 확인 | 타이틀, 문 열림, 입장 안내, 출근 카드, 손목시계, 결과 카드, 퇴근, 결말을 캡처로 직접 봤다(`docs/p2/evidence/title/editor/`) |
| 기존 소리 불변 | 48개 바이트 비교 일치 |

하지 않은 것: Quest 2, 3일차 플레이(자동 검사 없음), 걷기·순차 등장·자유 이동·P1 회귀, IL2CPP 플레이어 빌드, 새 음성 청취. 체크 끝난 에디터가 종료할 때 0xC0000005가 나는 것은 전부터 있던 현상이다.

참고: 첫 실행에서 `title.player_at_door` 1개가 실패했는데, Play 직후 프레임이 적어 플레이어를 옮기기 전에 검사한 것이었다. 검사가 그 위치를 기다리도록 고쳤다.

## 6. 남은 일
