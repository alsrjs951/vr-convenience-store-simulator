# 계산대에 상품 바로 올려두기: 바구니 제거 (2026-11-10)

> 사용자 요청: 계산대 위에 상품을 놔두는 것이 단순한 네모 상자인데, 실제 편의점에는 이런 상자가 없다. 그냥 계산대 위에 올려두는 방향으로.
>
> **상태: 코드 수정, 씬 재빌드, 시뮬레이터 검사, 화면 확인까지 끝났다.** 1일차 242/242, 2일차 330/330, 첫 1분 81/81(모두 외부 마우스 0). Quest 2에서는 보지 않았다. IL2CPP 플레이어는 다시 빌드하지 않았다. 커밋하지 않았다. 같은 날의 현금 결제 작업(`현금결제_금전출납기_2026-11-10.md`) 위에 얹었다.

## 1. 무엇을 가리킨 것으로 봤나

계산대 위에는 상자 모양이 둘 있었다.

- **빨간 상자**: 손님이 들고 와 계산대에 내려놓는 바구니. 주문 상품이 그 안에 서 있었다.
- **흰 상자**("동아편의점"): 스캔한 상품을 담는 비닐봉투 자리.

요청의 "상품을 놔두는 것", "그냥 계산대 위에 올려두는"은 빨간 상자로 읽었다. 흰 상자는 봉투 담기 규칙(주문의 "봉투 필요", 튜토리얼 4단계, 손님·점장 음성)이 걸려 있어 이번에 건드리지 않았다. 흰 상자를 말한 것이었다면 따로 바꿔야 한다(4장).

## 2. 바뀐 것

| | 전 | 후 |
|---|---|---|
| 계산대 위 | 빨간 상자 안에 상품이 한 줄로 서 있음 | 상자 없음. 상품이 계산대 위에 바로 놓임 |
| 놓이는 모습 | 손님이 서는 순간 상자와 상품이 한꺼번에 나타남 | 손님 쪽 위에서 계산대로 내려와 하나씩 놓임(첫 상품 0.24초, 다음부터 0.08초씩 늦게). 놓일 때 작은 소리 |
| 놓인 자세 | 정면을 보고 정확히 한 줄 | 정면을 보되 좌우로 ±7° 돌아가고 앞뒤로 조금 어긋남. 손으로 놓은 것처럼 |
| 줄 선 손님 | 손잡이 달린 빈 빨간 상자를 들고 있음 | 빈손 |

그대로인 것:

- 상품이 서 있는 자리(스캐너와 카드 단말기 사이)와 간격(25cm), 앞면이 점원을 보는 방향. 바코드는 여전히 돌려서 찾아야 한다.
- 상품은 손님이 계산대 앞에 선 순간에 만들어진다(Gaussian 예산). 줄 선 손님이 상품을 들고 다니지는 않는다.
- 떨어뜨린 상품은 3초 뒤 놓였던 자리로 돌아온다.
- 입구 옆 바구니 더미와 계산대 연장부의 철망 바구니는 매장 장식이라 그대로 두었다.

상품을 눕혀 놓는 것도 검토했지만 하지 않았다. 과자 봉지를 앞면이 위로 가게 눕히면 뒷면 바코드가 계산대에 닿아, 들어 올리지 않고 스캐너 유리로 밀기만 해도 찍힌다. "바코드를 찾아 돌린다"는 과제가 사라진다. 자리도 모자란다(눕힌 봉지 셋은 손님 접시와 카드 단말기 사이에 들어가지 않는다).

## 3. 코드

- `Assets/Scripts/Gameplay/CustomerDirector.cs`: `PutOnCounter`(자리·각도 정하고 상품 생성), `SetDown`(내려놓는 동작, 그동안 잡기 꺼 둠), `GoodsSetDown`(다 놓였는지). 바구니를 만들던 코드(`CreateBasket`, `PlaceBasket`, `BuildBasket`, `CounterBasket`, `BasketMaterial`)는 지웠다. `BasketAnchor`는 `GoodsAnchor`로 이름을 바꿨다.
- `Assets/Scripts/Gameplay/TutorialController.cs`: 첫 손님의 상품도 `PutOnCounter`로 놓는다.
- `Assets/Scripts/Gameplay/GameAudio.cs`: `StoreSound.SetDown`(진열 '착'과 같은 소리, 횟수는 따로 센다).
- 줄이 기우는 방향은 정해져 있다. 손님 접시 쪽 끝은 점원 쪽으로, 카드 단말기 쪽 끝은 손님 쪽으로 2cm. 가장 두꺼운 상품(10cm)이 7° 돌아가도 접시와 단말기에 닿지 않게 한 값이다.
- 각도와 어긋남은 주문 번호와 자리로 정해져서 같은 주문은 매번 같은 모습이다.

## 4. 검증

이 워크트리, 에디터와 XR Device Simulator. HMD 런타임은 꺼져 있었다.

| 항목 | 결과 |
|---|---|
| 씬 빌드 `P2StoreBuilder.Build` | 통과(조명 굽기 111초) |
| 1일차 `-p2-verify` | 242/242, S 98점, 매출 13,400/13,400원, 외부 마우스 0. 최종 코드로 돌렸다 |
| 2일차 `-p2-day2-verify -start-day 2` | 330/330, A 89점, 외부 마우스 0 |
| 첫 1분 `-p2-intro-verify` | 81/81, 외부 마우스 0 |
| 화면 | 계산대 위 상품(점원 시점, 가까이), 빈손으로 줄 선 손님을 직접 봤다 |

2일차와 첫 1분은 각도를 정하는 방식을 고치기 전에 돌렸다. 처음에는 시드를 준 난수를 썼는데, 이웃한 시드의 첫 값이 비슷해서 나란히 놓인 두 상품이 거의 같은 각도(0.7° 차이)로 돌아갔다. 해시로 바꾼 뒤에는 1일차만 다시 돌렸다. 범위(±7°, ±0.8cm)는 같다.

새로 보는 검사(주문마다 2개, 튜토리얼 2개):

- 상품이 다 놓일 때까지 기다린다(`goods_set_down`)
- 상품마다 가장 낮은 점이 계산대 윗면(0.9m)에 있고, 물리가 켜져 있고, 잡을 수 있고, 장면에 바구니가 없다(`goods_stand_on_the_bare_counter`)

바구니를 보던 검사 셋(계산대 바구니 있음, 줄 선 손님 수만큼 바구니, 튜토리얼 손님의 바구니)은 뺐다.

화면과 리포트: `docs/p2/evidence/counter_goods/` (`before_*`는 바꾸기 전 같은 날 화면).

하지 않은 것:

- Quest 2 확인. 상품이 내려오는 0.24~0.4초 동안 잡히지 않는 것이 손에 거슬리는지는 헤드셋에서 봐야 한다
- 3일차, 타이틀, 자유 이동 검사
- IL2CPP 플레이어 재빌드
