# UI 정리 (2026-11-10)

> 진단의 6번(UI). 3DGS 상품 학습이 GPU를 쓰는 동안 진행했다.
>
> **상태: 코드 수정, 1일차 검사 206/206(외부 마우스 0), 2일차 검사 299/300과 플레이 화면 확인까지 끝났다.** 2일차의 실패 1건은 UI와 무관한 Gaussian 예산 검사이고 7장에 적었다. Quest 2에서 글자가 읽히는지는 보지 않았다.

## 1. 왜 바꿨나

UI가 전부 같은 모양이었다. 매장 간판, 떠 있는 안내, 모니터 화면이 모두 남색 둥근 판에 흰 글자여서 무엇이 매장 물건이고 무엇이 게임 안내인지 구분되지 않았다. POS 화면은 품목이 없으면 머리글 한 줄뿐인 검은 화면이었다. 패널과 버튼은 알약처럼 둥글었다. 안내판은 단계와 할 일이 같은 굵기의 한 덩어리 글자였다.

## 2. 세 가지 모양

무엇인지에 따라 모양을 나눴다.

| 종류 | 모양 | 해당하는 것 |
|---|---|---|
| 매장 간판 | 동아 남색, 흰 글자 | 매장 이름, 구역 이름, 타이틀 문패 |
| 게임이 플레이어에게 하는 말 | 어두운 중립색 유리, 작은 모서리 | 근무 안내판, 결과 카드, 손목 화면, 조작 안내, 화살표 이름, 튜토리얼 이름표 |
| 매장의 화면 | 밝은 바탕, 줄 친 표, 각진 모서리, 남색 머리띠 | POS 화면, 주문 화면 |

## 3. 바뀐 것

- **POS 화면:** 머리띠("동아편의점", "POS 01 · 판매"), 열 이름(상품명, 수량, 금액), 줄 친 6행과 행마다 취소 버튼, 굵은 선 아래 합계와 받은 돈·거스름, 맨 아래 알림 띠. 수량이 이름 옆 글자에서 자기 열로 옮겨 갔다. 손님이 없을 때도 "0원"이 흐리게 보인다.
- **주문 화면:** POS와 같은 소프트웨어처럼 맞췄다. 머리띠에 손님 번호(없으면 "주문 확인"), 밝은 바탕에 품목 목록, 결제 수단과 봉투 표시, 시간 막대. 깜빡임은 밝은 호박색이다.
- **떠 있는 안내:** `WorldUi.Palette.Panel`을 남색에서 어두운 중립색으로 바꿨다. 이 색을 쓰는 패널이 한꺼번에 바뀐다.
- **모서리:** 반지름 22 → 10. 버튼과 표시가 알약 모양에서 작은 모서리의 사각형이 됐다.
- **안내판:** 첫 줄은 굵게, 나머지 줄은 82% 크기로 옅게 그린다("3/6 스캔" / "바코드 면을 스캐너 유리에", "2일차 정산 A · 90점" / 세부 줄). 계산대 위 안내판과 2일차 진열대 옆 입고 안내 3곳에 적용했다.

검사가 읽는 글자(`BoardText`, `LastOutcome`, `GuideTexts`)와 취소 버튼의 위치·크기는 그대로다. 안내판은 글자를 담는 `Text`를 그대로 두고 그리지만 않게 한 뒤, `HeadlineText`가 그 글자를 읽어 제목과 본문 두 개로 그린다. 튜토리얼과 검사가 글자를 쓰고 읽는 방식은 바뀌지 않았다.

## 4. 코드 지도

- `Assets/Scripts/Gameplay/WorldUi.cs`: `Palette`(Panel, Paper, Ink, InkDim, Rule, Band), `CornerPixels`, `Square`
- `Assets/Scripts/Gameplay/POSScreen.cs`: 화면 배치와 `Refresh`
- `Assets/Scripts/Gameplay/CustomerDirector.cs`: `Start`의 주문 화면 배치, `RefreshSpecial`, `SetHudVisible`
- `Assets/Scripts/Gameplay/HeadlineText.cs`: 제목·본문 표시. `GameManager.Awake`와 `IntakeDirector.Awake`에서 붙인다
- 화면: `docs/p2/evidence/ui_screens/` (`before_*`, `after_*`)

씬은 다시 빌드하지 않았다. 패널은 실행 때 만들어진다.

## 5. 검증

이 워크트리, 에디터와 시뮬레이터. `ns-train` 1개가 GPU를 쓰는 중이었다.

| 항목 | 결과 |
|---|---|
| 1일차 `-p2-verify` | 206/206, S, 외부 마우스 0, 데스크톱 평균 177fps. 과다 스캔 알림, 행 취소, 현금 거스름 포함. 안내판 수정 전에 돌렸다 |
| 2일차 `-p2-day2-verify -start-day 2` | 299/300, A, 외부 마우스 0, 176fps. 안내판 수정 뒤에 돌렸다. 실패는 `p4.peak_gaussians_in_budget` 1건(7장) |
| 첫 1분 `-p2-intro-verify` | 72/72이지만 외부 마우스 2558.7이 들어가 무효. 화면 확인용으로만 썼다 |
| 화면 | 튜토리얼, 품목이 찍힌 POS, 알림 띠, 현금 결제, 1·2일차 정산, 2일차 주문을 직접 봤다 |

하지 않은 것:

- Quest 2에서 밝은 화면이 눈부시지 않은지, 표의 작은 글자가 읽히는지
- 3일차, 타이틀, 자유 이동 검사. 3일차의 특수 요청 표시(전자레인지, 온수, 1+1)는 색만 바꿨고 화면으로 보지 않았다
- 안내판 수정 뒤의 1일차 재검사와 최종 리포트(3일 근무) 화면
- 플레이어 재빌드

## 6. 남은 일

- 타이틀 패널과 설정 화면은 모서리만 바뀌었다.
- 입고 상자 라벨, 유통기한 표시, 진열 칸 표시는 색과 배치를 그대로 두었다.

## 7. 2일차 Gaussian 예산 검사 실패 (UI와 무관, 전부터 있던 문제)

2일차 검사에서 `p4.peak_gaussians_in_budget`가 실패했다: 최대 1,557,457개(렌더러 19개), 기준 150만.

원인을 확인하려고 기준 커밋 `a026078`을 임시 워크트리에 꺼내 같은 검사를 같은 조건(학습 중)에서 돌렸다. 결과는 299/299 통과, 최대 1,369,228개(렌더러 17개)였다.

- 두 실행의 차이 188,229개는 1번 주문의 상품 두 개(꼬깔콘 68,251 + 콘칩 119,978)와 정확히 같다.
- 이번 실행에서는 1번 손님이 계산대에 30초 일찍 도착했다(1번 주문 완료 106.9초, 기준 실행은 136.9초). 점원이 아직 진열 중일 때 그 손님의 상품이 계산대에 놓였고, 진열 직후에 재는 표본에 함께 잡혔다.
- 손님이 들어오는 간격과 구경 시간은 시드 없는 `Random`이다(`CustomerDirector`). 그래서 이 검사는 실행마다 결과가 달라질 수 있다.
- 씬의 진열 칸 설정(`DisplayOnly`, 병합본 참조)은 `a026078`과 지금이 같다.

정리하면, 오늘의 변경이 만든 문제가 아니라 **"점원이 진열하는 동안 다음 손님의 상품이 계산대에 놓이면 150만을 넘는다"는 상태가 원래 있었고, 기준 실행에서는 그 순간이 표본에 안 잡혔던 것**이다. 첫 1분 개선 문서의 "2일차 최대 1,369,228"은 실제 최대보다 낮게 잡힌 값이다. 상한 200만 안에는 있다. 고치지 않았다. 고치려면 작업 칸의 근거리 전환을 더 줄이거나, 표시 진열의 원거리본을 가볍게 하거나, 목표를 조정해야 하고, 그 판단에는 Quest 2 프레임 측정이 필요하다.
