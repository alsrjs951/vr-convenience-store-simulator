# Quest 2 실기 점검표 (G1-H)

첫 실기 점검을 위한 절차와 도구다. **유선 Link 측정은 아직이다.** 11/07에 Air Link(무선)로 리허설만 했다(아래 "Air Link 리허설", 판정 아님). 유선 측정 결과는 점검 뒤 `docs/perf/perf_log.csv`와 결과 문서에 기록한다.

순서는 PC 설정, 측정 1(게이트, 약 3분), 측정 2(1일차 플레이, 약 5분)다. 측정 2까지 끝나면 구현 문서 9.1절 G1-H 항목과 자유 이동에서 미뤄 둔 결정을 함께 처리할 수 있다.

## 1. PC와 헤드셋 설정 (처음 한 번)

준비물은 Quest 2, 충전된 Touch 컨트롤러 2개, USB-C 데이터 케이블이다. 메뉴 이름은 Meta의 [Link 문서](https://developers.meta.com/vr/documentation/unity/unity-link/)와 [Debug Tool 문서](https://developers.meta.com/vr/documentation/native/pc/dg-debug-tool/?locale=en_US) 기준이다. 앱 업데이트로 달라질 수 있다.

- [ ] **앱 설치:** [Meta Horizon Link](https://www.oculus.com/download_app/?id=1582076955407037)를 설치하고 로그인한다. 구현 문서의 "Meta Quest Link"가 지금 이 이름이다.
- [ ] **OpenXR 런타임:** 앱에서 **Settings > General > OpenXR Runtime** 옆의 **Set Meta Horizon Link as active**를 누른다. 활성화되면 버튼이 회색이 된다. 11/07에 이 PC는 등록을 마쳤다(레지스트리 `ActiveRuntime` 확인).
- [ ] **알 수 없는 출처(필수):** PC 앱 설정의 **알 수 없는 출처**(영문 Unknown Sources)를 켠다. 우리 빌드는 Meta 스토어 앱이 아니라서, 꺼져 있으면 게임이 실행돼도 헤드셋에는 "알 수 없는 출처라 신뢰할 수 없다"는 안내만 나오고 화면이 넘어오지 않는다. 11/07 리허설에서 이렇게 막혔고 켠 뒤에 풀렸다. 메뉴 위치는 외부 안내 문서 기준 Settings > General이다.
- [ ] **케이블 시험:** **Devices > 기기 선택 > Device Setup > Link Cable > Continue > Continue > Test Connection**에서 **Compatible connection**을 확인한다.
- [ ] **주사율 72Hz:** 앱의 기기 그래픽 설정에서 Refresh Rate를 72Hz로 둔다. **Render Resolution 값을 적어 둔다.** 메뉴 위치는 위 Meta 문서에 나오지 않아 앱에서 찾아야 한다.
- [ ] **헤드셋:** **Settings > Quest Link**를 켜고 **Launch Quest Link**를 누른다. 펌웨어 버전을 적어 둔다.
- [ ] **측정용 설정:** `C:\Program Files\Meta Horizon\Support\oculus-diagnostics\OculusDebugTool.exe`를 관리자 권한으로 연다.
  - **Service > (PC) Asynchronous Spacewarp = Disabled.** 켜 두면 프레임이 밀릴 때 36fps로 내려가 판정이 흐려진다.
  - **HUDs > Visible HUD = Performance**, **Performance HUD > Mode = Performance Summary.** 측정기 수치와 대조하는 용도다.
  - 앱을 다시 켜면 Spacewarp 설정이 돌아간다는 [사용자 보고](https://forums.flightsimulator.com/t/asynchronous-spacewarp-setting-does-not-stick/346260)가 있다. 측정 전마다 확인한다.

여기까지 하면 알려 주세요. OpenXR 런타임 등록과 헤드셋 연결은 제가 확인할 수 있습니다.

## 2. 측정 1: 게이트 (G1-H)

구현 문서 9.1절의 장면(1m 앞 상품 3개, 30cm 앞 상품 2개)을 30초씩 3회 잰다. 1일차 진행 없이 이 장면만 나온다.

헤드셋을 연결하고 Link를 켠 **뒤에** 실행한다. 실행 중에 연결하는 것은 지원하지 않는다. 헤드셋을 벗어 두었다면 연결이 끊겼을 수 있으니, **실행 직전에 헤드셋을 쓰고 Link 홈 화면이 보이는지 확인한다.** 리허설에서 게이트를 마치고 벗은 뒤 1일차를 실행했더니 연결이 끊겨 있어 게임이 헤드셋에 뜨지 않았다.

```bash
C:/Projects/vr-convenience-store-simulator/Builds/Store/VRStore.exe -hmd-perf C:/Projects/vr-convenience-store-simulator/docs/p2/evidence/quest2/gate1 -hmd-gate -screen-fullscreen 0 -screen-width 1920 -screen-height 1080 -logFile C:/Projects/vr-convenience-store-simulator/docs/p2/evidence/quest2/gate1.log
```

1. 헤드셋을 쓰면 눈앞에 안내문이 따라온다.
2. 정면을 보고 **오른손 A 버튼**을 누른다. 진동이 한 번 오고 상품이 나타난다. A가 안 되면 PC 스페이스바도 같은 동작을 한다.
3. **30초 동안 고개를 움직이지 않는다.** 끝나면 진동이 한 번 더 온다. 이것을 3회 반복한다.
4. "측정 끝"이 나오면 상품을 보며 아래를 확인한다.
5. 헤드셋을 벗고 PC에서 창을 닫는다(Alt+F4).

**판정은 측정기가 한다.** 3회 모두 평균 72fps 이상(0.5 허용), 프레임 드롭 5% 미만이면 통과다.

**직접 볼 것:**

- [ ] 왼쪽 눈과 오른쪽 눈을 번갈아 감아도 양쪽 모두 상품이 보인다.
- [ ] 상품이 이중으로 겹치거나 공중으로 떠 보이지 않고, 1m와 30cm의 거리감이 맞다.
- [ ] 머리를 돌릴 때 상품이 깜빡이거나, 뒤쪽이 앞으로 튀어나오지 않는다.
- [ ] 30cm 상품의 브랜드명과 글자가 읽힌다. 어느 상품이 안 읽히는지 적는다. 3DGS 품질은 추후 과제이므로 여기서는 기록만 한다.

## 측정기 (`HmdPerfRecorder`)

`-hmd-perf <폴더>`를 줄 때만 동작한다. 평소 플레이에는 아무 영향이 없다. 폴더에 `hmd_report.json`과 양쪽 눈 사진(`*_left.png`, `*_right.png`)을 남긴다.

| 인수 | 동작 |
|---|---|
| `-hmd-gate` | 1일차 대신 G1-H 장면을 30초씩 3회 잰다 |
| `-hmd-render-scale <값>` | URP 렌더 스케일을 바꾼다 (미달 시 재측정용) |
| `-hmd-sh <0~3>` | 게이트에서 상품의 SH 차수를 낮춘다 |
| `-hmd-worn` | A를 누르지 않아도 처음부터 플레이 기록으로 친다. 측정 2에서 쓴다 |
| `-hmd-auto`, `-hmd-seconds`, `-hmd-hold-eye-height` | Mock 시험 전용 |

리포트의 장비 정보(컨트롤러, 눈 해상도, 주사율, 추적 기준)는 헤드셋을 쓴 동안 읽은 값을 남긴다. 창을 닫을 때는 보통 헤드셋을 벗은 뒤라 컨트롤러가 빠지기 때문이다. `xr_active`는 기록 중 한 번이라도 XR이 켜졌는지, `controllers`는 기록 중 본 컨트롤러 전부, `haptic_pulses`는 측정기가 실제로 보낸 진동 횟수다.

**구현 문서의 p95 13.5ms 기준은 프레임 간격으로 잴 수 없다.** 72Hz에서는 런타임이 프레임을 13.89ms 간격으로 맞추므로 간격의 p95는 항상 13.5ms를 넘는다. 그래서 측정기는 다음과 같이 나눠 잰다. 이 해석은 제 판단이며 구현 문서는 고치지 않았다. M3 전에 정해야 한다.

- 프레임 간격: 평균 fps, 드롭 판정. G1-H 기준이다.
- GPU 시간과 CPU 작업 시간: p95 13.5ms 비교. `work_budget_pass`로 남긴다. Link 인코딩과 컴포지터 시간은 빠져 있으니 Debug Tool HUD와 대조한다.

## 알고 있는 문제

이번 준비 중에 드러났고 고치지 않았다. 실기에서 얼마나 거슬리는지 보고 정한다.

- **먼 글자가 가까운 상품 위에 그려진다.** 상품은 투명 오브젝트보다 먼저 그려지고 깊이를 남기지 않는다(`BeforeRenderingTransparents`). 그래서 눈에서 약 1.2m 떨어진 POS 화면이 30cm 앞 상품을 덮는다. 접시 이름표와 포인터 선도 같다. 증거: `precheck/mock_gate_left.png`. 양쪽 눈의 거리감과 어긋나므로 실기에서 더 거슬릴 수 있다. **Quest 2 리허설 사진에서도 나왔다**(아래 "Air Link 리허설").
- **근무 중 프레임이 튄다.** 데스크톱 플레이어에서 근무 구간 최대 74.7ms(GPU 61.0ms), 5분 동안 빠진 프레임 39개다. 손님 상품을 그때 만드는 비용으로 추정하며(부하 측정 문서) 확인하지는 않았다. 실기 리포트의 `worst`에서 시각을 본다.
- **시작 위치를 맞추는 기능이 없다.** 게임은 리그 위치에서 시작하고 실제로 서 있는 위치와 방향만큼 어긋난다. 계산대를 넘어가 있으면 `RoomScaleBody`가 밀어내지만, 방향은 그대로다. 어긋나면 일단 헤드셋의 시점 재조정(Oculus 버튼 길게)을 써 본다. 기획서의 시점 재조정 버튼 결정(11/12)에 넣을지 이번 결과로 판단한다.
- **Mock 화면의 흰 포인터 선은 판단하지 않는다.** Mock의 컨트롤러가 머리 위치에 있어서 굵게 보이는 것으로 추정한다. 실제 모습은 실기에서 본다.
- **매장에 천장이 없다.** 전체 매장 배치(P3-K1) 전까지의 임시 상태다.

3. **헤드셋을 벗은 뒤 연결이 끊겼다.** 게이트를 마치고 벗은 뒤 1일차를 PC에서 실행했더니(18:05) 연결이 끊겨 있어 XR 세션이 `IDLE`에 머물렀다. 2장에 실행 직전 확인을 넣었고, 18:46에 헤드셋을 쓴 상태를 확인한 뒤 다시 실행해 끝까지 했다.
4. **측정기 버그 세 개를 고쳤다.**
   - 진동: 오른손 컨트롤러를 시작할 때 한 번만 찾았다. 1차는 PC에서 실행돼 시작 시점에 컨트롤러가 아직 켜지지 않았던 것으로 보이고(`haptic_hand` 빈 값), 2차는 헤드셋을 쓴 채 실행돼 찾았다(`Near-Far Interactor`). 이제 진동을 보낼 때 다시 찾고, 보낸 횟수를 `haptic_pulses`에 남긴다.
   - 종료 시 예외: 1일차 창을 닫을 때 보관해 둔 디스플레이 객체가 이미 해제돼 `NullReferenceException`이 났고 리포트가 저장되지 않았다. 이제 디스플레이를 쓸 때마다 실행 중인 것을 찾고, 장비 정보를 못 읽어도 리포트는 저장한다. 헤드셋을 쓴 채 1일차를 하고 창을 닫았다면 구간을 닫는 단계에서 같은 예외가 나 마지막 구간을 잃었을 수 있다.
   - 종료 시 장비 정보 덮어쓰기: 창을 닫을 때 헤드셋을 벗은 뒤의 값(컨트롤러 0개)으로 리포트를 덮어썼다. 이제 쓴 동안 읽은 값을 남긴다.

증거: `docs/p2/evidence/quest2/airlink_rehearsal/` (`gate/`는 2차 결과, `gate.log`는 2차 로그, `gate_first_run_console.txt`는 1차 요약, `day1.log`는 연결이 끊긴 1일차 실행, `day1b/`와 `day1b.log`는 끝까지 한 1일차).

"메인 최종 플레이어"는 11/07 19:31 빌드(카드 단말기 수정 후)다. 18:16 빌드에서 측정기를 고쳤다. 이 PC에 Meta 런타임이 등록된 뒤라, XR을 끈 검사는 `XR_RUNTIME_JSON`을 없는 파일로 지정해 돌렸다(`loader=none`, 시뮬레이터 켜짐 확인). 검사하는 동안 Link에 VRStore 접속 기록은 없었다. 창을 닫을 때의 예외는 Meta 런타임에서 디스플레이가 먼저 해제되는 경우였는데, 그 상황 자체는 재현하지 못했다. 다음 실기에서 확인한다.

**Mock으로 확인한 것:**

- 추적 기준이 `Floor`로 잡히고, 런타임이 있을 때 백그라운드 실행과 `IgnoreFocus`가 켜진다.
- 왼쪽과 오른쪽 눈이 각각 렌더링되고, 상품과 일반 메시가 같은 방향으로 어긋난다. 눈으로 대조했다.
- A 버튼이 `/OculusTouchControllerOpenXR1/primarybutton`에 바인딩된다. 스페이스바로 시작하는 경로는 가상 키보드로 3/3 동작했다.

**확인하지 못한 것:**

- A 버튼을 실제로 눌렀을 때와 진동. Mock에서는 버튼 상태를 넣을 수 없었다.
- Quest의 머리와 손 추적, 실제 입체감, 72Hz에서의 프레임, Link 인코딩과 컴포지터 부하, 소리.
- Mock의 눈 시점은 실제 헤드셋과 다르다(IPD 22mm, 눈당 1512×1680). 양쪽 눈 확인은 "한쪽이 비지 않고 시점이 나뉜다"까지만 뜻한다.

Mock 참고값(G1-H 장면, 상품 5개, 458,871 Gaussian, 3회 비슷함): GPU 평균 3.57ms, p95 3.74ms, CPU 작업 p95 2.06ms. VSync 없는 값이고 눈당 픽셀도 적어서 **G1-H 판정에 쓰지 않는다.**

측정 중 잡은 측정기 오류가 하나 있다. CPU 작업 시간을 처음에 메인 스레드 시간에서 대기 시간을 빼서 계산했는데, 메인 스레드 시간에는 대기가 이미 빠져 있어서 플레이어에서 항상 0.00으로 나왔다. 그대로였다면 실기에서 CPU 기준이 무조건 통과했을 것이다. 메인·렌더 스레드 중 큰 값으로 고쳤다.
