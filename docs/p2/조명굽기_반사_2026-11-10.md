# 조명 굽기와 반사 (2026-11-10)

> 진단의 4번(재질과 조명). 3DGS 상품 학습이 GPU를 쓰는 동안, GPU와 플레이 검사 없이 할 수 있는 작업으로 골랐다.
>
> **상태: 씬 재빌드(굽기 포함), 정지 화면 전후 비교, 출근 흐름 검사 75/75(외부 마우스 0)까지 끝났다.** Quest 2와 프레임 측정은 하지 않았다.

## 1. 왜 바꿨나

매장 전체가 균일한 환경광 하나로 밝혀져 있었다. 그림자가 없어서 선반 안쪽과 바깥이 같은 밝기였고, 바닥의 빛과 가구 그림자는 텍스처에 그려 넣은 것이었다. 금속은 비칠 방이 없어 하늘색을 반사했다. 물체가 바닥에 놓여 있다는 느낌이 약했다.

## 2. 바뀐 것

| 항목 | 전 | 후 |
|---|---|---|
| 광원 | 3색 환경광 + 약한 직사광 | 천장 조명 줄 22개, 쇼케이스 캐노피와 단 조명 5개, 문 밖 낮 빛 1개를 구운 면광원으로. 환경광은 거의 끔 |
| 그림자 | 없음(바닥 텍스처에 그림) | 라이트맵 3장(최대 1024, 32텍셀/m, AO 포함) |
| 바닥 텍스처 | 빛 띠, 반사 줄무늬, 접촉 그림자가 그려진 `floor_baked` | 테라조만 있는 `floor_terrazzo`. 가구 위치 목록을 손으로 맞춰 줄 필요가 없어졌다 |
| 벽 | 세로 그라데이션 텍스처 `wall_shade` | 단색 페인트. 밝기 차이는 구운 빛에서 나온다 |
| 반사 | 기본 하늘 | 매장 가운데 반사 프로브 1개(256, 방 크기로 박스 투영). 스테인리스, 유리, 윤나는 바닥에 매장이 비친다 |
| 움직이는 물체 | 환경광 | 조명 프로브 495개(바닥 아래부터 천장 위까지, 벽에서 벽까지). 손님, 손, 상자, 전자레인지 문 |
| 실행 중 비용 | 실시간 직사광 1개 | 실시간 광원 0개. 추가된 것은 라이트맵 샘플과 박스 투영 계산뿐이다 |

3DGS 상품은 조명을 받지 않으므로 그대로다. 충돌체와 게임 규칙은 건드리지 않았다. 내려받은 에셋은 없다.

## 3. 일부러 하지 않은 것

- **실사 PBR 텍스처 교체:** 계획에는 있었지만 넣지 않았다. 구운 빛과 반사를 넣고 보니 생성한 테라조 바닥과 단색 벽으로도 충분히 실제처럼 읽혔다. 부족하다고 판단되면 그때 후보를 골라 승인받는다.
- **SSAO, 실시간 그림자:** 실행 중 비용이 붙는다. Quest 2의 72fps 여유를 재지 않은 상태라 넣지 않았다.

## 4. 코드 지도

- `Assets/Editor/P3StoreLighting.cs`: 정적 표시, 면광원, 프로브 격자, 반사 프로브, 굽기 설정, 굽기 뒤 프로브 보정
- `P2StoreBuilder.BuildScene` 끝에서 씬을 저장한 뒤 `P3StoreLighting.Bake`를 부른다
- `P3Meshes`: 둥근 상자와 각기둥에 라이트맵용 두 번째 UV. `P3StoreDressing.ConfigureImports`: 가져온 모델에 `generateSecondaryUV`
- 결과물: `Assets/Scenes/StoreScene/`(라이트맵 3장, 반사 프로브, `LightingData.asset`, 약 15MB), `Assets/Settings/StoreLighting.lighting`
- 화면: `docs/p2/evidence/store_lighting/` (`compare_*.jpg`는 위가 전, 아래가 후. `play_*.png`는 플레이 화면)

### 실행

```text
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod P2StoreBuilder.Build -quit            # 굽기 포함, 약 2분
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod P2StoreBuilder.Build -no-bake -quit   # 굽지 않음, 예전의 균일한 빛
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod P3StoreLighting.Rebake -quit          # 씬은 그대로 두고 빛만 다시 굽기
```

밝기는 `P3StoreLighting`의 `StripIntensity`(20), `CaseIntensity`(14), `DaylightIntensity`(6), `CeilingFill`(0.3)로 맞춘다.

## 5. 거쳐 온 문제

1. **바닥과 천장이 검게 나옴.** Unity 기본 Quad에는 두 번째 UV가 없어서 프로브 조명으로 돌려 놓았던 것이 원인이었다. Quad는 첫 번째 UV로 구워도 되므로 라이트맵을 받게 했다.
2. **인쇄면이 어둡게 나옴.** 벽과 바닥에서 몇 mm 떠 있는 인쇄면(스티커, 필름, 가격표)을 굽기에서 뺐더니 프로브 조명만 받아 어두웠다. 라이트맵을 받되 그림자는 드리우지 않게 했다.
3. **격자 밖은 빛이 0.** 프로브 격자 바깥의 점은 가까운 프로브 값이 아니라 환경광(거의 검정)을 받는다. 격자를 바닥 아래와 천장 위까지 넓히고, 집기 속이나 방 밖에 있어 어둡게 구워진 프로브(495개 중 270개)는 방을 본 가장 가까운 프로브 값으로 바꾼다.
4. **정지 렌더에서 금속이 검게 나옴.** 배치 모드로 연 씬은 구운 반사 프로브를 그 이미지가 다시 지정될 때까지 검게 그린다(Unity 6000.3.26f1). 프로브 이미지 자체는 정상이었다. `RenderViews`가 렌더 전에 다시 지정하게 했다. 플레이 화면에서는 따로 손대지 않아도 반사가 나온다.

## 6. 검증

이 워크트리, 에디터와 시뮬레이터. 그동안 `ns-train` 1개가 GPU를 쓰고 있었다.

| 항목 | 결과 |
|---|---|
| 씬 재빌드 `P2StoreBuilder.Build` | 통과, 123초(그중 굽기 109초). 라이트맵 대상 579개, 두 번째 UV 없는 메시 0 |
| 고정 시점 렌더 18장 | 전후를 나란히 놓고 직접 봤다 |
| 프로브 값 | 통로, 계산대 뒤, 바닥 높이, 전자레인지 자리, 문 밖에서 0이 아닌 것을 읽어 확인(바닥 높이 위쪽 방향 0.95) |
| 출근 흐름 `-p2-title-verify` | 75/75, 외부 마우스 0, 데스크톱 평균 308fps. 종료 때 0xC0000005는 전부터 있던 것 |
| 플레이 화면 | 손님이 프로브 빛을 받아 자연스럽게 보이고, 상품과 UI는 전과 같다. 모니터 받침대에 반사가 나온다 |

하지 않은 것:

- Quest 2 확인과 프레임 측정. 실시간 광원은 줄었지만 헤드셋에서 밝기가 어떻게 느껴지는지는 모른다
- 1·2일차, 자유 이동, 첫 1분 검사, 3일차 플레이, 플레이어 재빌드
- 전자레인지 문이 열릴 때와 타이틀의 유리문이 움직일 때의 모습(프로브 조명이라 문제없을 것으로 보지만 화면으로 보지 않았다)

## 7. 남은 일

- 전자레인지 수납장 앞면처럼 넓고 흰 면에 옅은 얼룩이 보인다. 샘플 수를 올리면 줄지만 굽는 시간이 3분으로 늘어 지금 값으로 뒀다.
- 쇼케이스 단 앞의 남색 레일과 검은 곤돌라 안쪽이 전보다 어둡다. 상품을 채우면서 다시 본다.
- 빌드가 2분 길어졌다. 모양과 무관한 빠른 재빌드는 `-no-bake`로 하되, 그 씬은 커밋하지 않는다.
- 진단의 나머지: 2번 상품으로 채우기, 5번 소품, 6번 UI.
