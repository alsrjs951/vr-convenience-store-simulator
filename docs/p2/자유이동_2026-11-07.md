# 자유 이동 구현·시뮬레이터 검증 (2026-11-07)

마일스톤 M2의 자유 이동 부분이다(구현 문서 D11, 5.1절). 1일차 게임 루프가 있는 `StoreScene`에 걷기, 회전, 비네트, 충돌을 넣었다.

## 무엇이 확인됐고 무엇이 안 됐나

| 구분 | 상태 |
|---|---|
| **실험 성공** | XR Device Simulator의 왼손·오른손 스틱 입력으로 메인 최종 IL2CPP 플레이어에서 자유 이동 85/85(2회), 1일차 129/129, 걷기를 섞은 1일차 142/142 통과. P1 회귀는 닭다리·신라면 각 48/48. 실제 마우스 입력 0 |
| **실제 품질** | 미평가. 사람이 해 본 적이 없다. 수치는 설정대로 움직인다는 뜻이지 편하다는 뜻이 아니다 |
| **HMD 검증** | **안 함.** Quest 2 미연결. 조작감, 멀미, 실제 썸스틱 입력, 비네트 세기, 머리 내밀기 한계가 적절한지 모두 미확인. OpenXR Mock 런타임으로는 스틱 바인딩까지만 확인했다 |

## 구현한 내용

XRI Starter Assets 리그에 대부분 이미 있어서, 값을 맞추고 쓰지 않는 기능을 껐다. `StoreScene`은 생성물이므로 모두 `P2StoreBuilder.ConfigureLocomotion`에 있다. 샘플 프리팹은 건드리지 않았고 P1 씬도 영향받지 않는다.

| 항목 | 리그 원래 상태 | 지금 |
|---|---|---|
| 왼손 이동 | `DynamicMoveProvider`, 2.5m/s, 머리 기준, 옆걸음 | **1.5m/s**, 나머지 그대로 |
| 오른손 회전 | Snap Turn 45°, 스틱을 뒤로 당기면 180° 회전 | 45°만. 180° 회전 끔 |
| 텔레포트 | 제공자·광선 켜짐, 오른손 스틱을 앞으로 밀면 조준 | 제공자·광선 끔, 입력 참조 제거 |
| 점프, 등반, 부드러운 회전 | 켜짐(A 버튼 점프 높이 1.25m) | 끔 |
| 비네트 | 리그에 없음 | `TunnelingVignette`를 카메라 자식으로 추가, 이동·스냅 회전에 연결. 샘플 기본값(조리개 0.7, 페더 0.2, 페이드 0.3초). 스냅 회전은 한두 프레임에 끝나므로 페이드인을 끝까지 하도록 잠금 |
| 충돌 캡슐 | 반지름 0.1, 스킨 0.08, Ignore Raycast 레이어 | 반지름 **0.2**, 스킨 0.02(기본값이면 벽에서 0.28m에 멈춤), **`Player` 레이어(14번, 신설)**, Default와만 충돌 |
| 실제 걸음 | 캡슐이 매 프레임 머리 밑으로 순간 이동 | `RoomScaleBody`(아래) |

`Player` 레이어 덕분에 카드·화폐(`PaymentProp`)도 캡슐과 부딪히지 않는다. 빌더가 `TagManager`와 `DynamicsManager`에 이 레이어만 추가한다. 다른 레이어끼리의 충돌은 그대로다.

### 실제 걸음에서 계산대를 뚫던 문제

**XRI 기본 동작으로는 계산대를 넘어갈 수 있었다.** 캡슐이 머리를 따라 계산대 안으로 들어가도 아무 일이 없다가, 스틱을 누르는 순간 PhysX가 겹침을 풀면서 반대편으로 밀어낸다. 측정값: 머리 z=0.499(계산대 앞면 0.35)에서 스틱을 옆으로 0.3초 누르자 머리가 **z=1.171, 손님 쪽**으로 튀었다. 스크린샷으로도 확인했다(`evidence/locomotion/before_fix/`). 계산대 위로 몸을 숙이고 스틱을 건드리기만 해도 일어날 수 있어 고쳤다.

`RoomScaleBody`(XRI의 `IXRBodyPositionEvaluator` 구현)의 규칙:

1. 캡슐은 머리 밑을 따라가되 장애물에 막히면 거기서 멈추고 옆으로 미끄러진다.
2. 머리는 캡슐에서 **0.2m까지** 내밀 수 있다. 계산대 너머로 손을 뻗을 때 세상이 밀리지 않게 하려는 값이다.
3. 그보다 더 걸어 들어가면 리그가 뒤로 밀려 머리가 더 나아가지 못한다. 벽 앞에서는 머리가 벽 표면 앞에서 멈춘다.

열린 곳에서는 캡슐이 머리 바로 밑에 있어 XRI 기본 동작과 같다.

## 실행 방법

시뮬레이터 조작(코드 `XRDeviceSimulator`, `XR Device Controller Controls` 확인). 한 손을 선택하면 다른 손의 스틱은 `I/J/K/L`로 간다.

| 입력 | 동작 |
|---|---|
| `Y`(오른손 선택) 후 `I/J/K/L` | **왼손 스틱: 앞/왼쪽/뒤/오른쪽 걷기** |
| `Y`(오른손 선택) 후 `A`/`D` | **오른손 스틱: 왼쪽/오른쪽 45° 회전** |
| `T`(왼손 선택) 후 `W/A/S/D`, `J`/`L` | 왼손 스틱, 오른손 스틱(자동 시험은 지나가지 않음) |
| 손 선택 없음(시작 상태) `W/A/S/D` | 머리 자체 이동. **이동 제공자를 지나지 않으며 실제 걸음에 해당** |

자동 검증(창이 뜨므로 마우스를 건드리지 않는다):

```powershell
Unity.exe -projectPath <프로젝트> -executeMethod P2StoreBuilder.VerifyEditor -p2-locomotion-verify -p2-evidence <출력폴더> -logFile verify.log
Builds\Store\VRStore.exe -p2-locomotion-verify -p2-evidence <출력폴더> -screen-width 1920 -screen-height 1080 -screen-fullscreen 0 -logFile player.log
Builds\Store\VRStore.exe -p2-verify -p2-walk -p2-evidence <출력폴더> -screen-width 1920 -screen-height 1080 -screen-fullscreen 0 -logFile player.log
```

`-p2-walk`는 1일차를 돌리면서 주문마다 다른 자리로 걸어가고 물건을 든 채 걷고 돈다. 빼면 기존 129개 검사 그대로다.

### 이동 (왼손 스틱, 플레이어)

앞, 뒤, 옆, 대각선, 고개 숙이고 걷기, 스냅 회전 뒤 걷기까지 10회 측정.

| 항목 | 결과 |
|---|---|
| 평균 속도 | 모두 1.500m/s. 대각선도 같다(2.12로 빨라지지 않음) |
| 처음 0.1초 속도 | 1.500m/s. 가속 없음 |
| 방향 오차 | 최대 0.42°. 대부분 마우스로 머리를 돌릴 때 생긴 오차다 |
| 머리 높이 변화 | 0.0000m. 흔들림 없음 |
| 키를 뗀 뒤 더 간 거리 | 0.000m. 감속 없음 |

속도는 게임 시계로 쟀다. 이동 제공자가 같은 시계로 계산하므로 1.500은 설정값이 그대로 적용된다는 확인이다. `timeScale`을 바꾸는 코드는 없다. 키 입력은 항상 스틱을 끝까지 민 값이다.

### 회전 (오른손 스틱)

- 한 번에 정확히 45.00°, 8번이면 360°로 돌아온다. 회전 중 머리 위치 변화 0.0000m.
- 회전 뒤 앞으로 걸으면 돌아간 머리 방향으로 간다.
- 1.3초 누르고 있으면 3번 돈다(샘플 기본값, 0.5초 간격).
- 스틱을 앞으로 밀어도 뒤로 당겨도 아무 일이 없다. 텔레포트 광선이 나오지 않는다.

### 비네트

|---|---|---|---|
| 멈춤 | 1.0(효과 없음) | 0.399 | 0.396 |
| 걷는 중 | 0.7 | 0.000 | 0.396 |
| 멈추고 0.6초 뒤 | 1.0 | 0.407 | 0.396 |

### 충돌 (왼손 스틱)

닿을 때까지 걸어간 뒤에도 더 밀었다. 멈춘 것만으로는 끼어서 멈춘 경우와 구별되지 않으므로, 멈춘 위치가 면에서 정확히 캡슐 반지름 + 스킨(0.22m)인지와 이동 내내 면을 넘지 않았는지를 함께 본다.

| 장애물 | 면 위치 | 멈춘 위치 |
|---|---|---|
| 계산대 앞쪽 | z=0.35 | z=0.130 |
| 계산대 뒤쪽(손님 쪽에서 접근) | z=0.95 | z=1.170, 손님 쪽에 남음 |
| 뒷벽 | z=-2.45 | z=-2.230 |
| 왼쪽 벽 | x=-4.45 | x=-4.230 |
| 오른쪽 벽 | x=4.45 | x=4.230 |
| 앞벽 | z=5.45 | z=5.230 |
| 진열대 A | z=2.95 | z=2.730 |

모두 면을 넘은 프레임이 없다. 계산대에 비스듬히 밀면 옆으로 미끄러진다.

| 시험 | 결과 |

### 손 입력과의 충돌 (`-p2-walk`)

주문마다 다른 자리(계산대에 붙은 곳 포함)에서 일을 처리해도 1일차 전체가 그대로 통과했다.

| 시험 | 결과 |
|---|---|
| 상품·카드를 든 채 1.5m/s로 걷기 | 계속 쥐고 있음, 걷는 중 최대 0.040m 처짐, 멈추면 0.000m |
| 든 채 스냅 회전(손이 한 프레임에 0.54~0.65m 이동) | 계속 쥐고 있음, 0.7초 뒤 손에서 0.001m |
| 카드를 캡슐 안으로 가져가기 | 리그 이동 0, 목표에서 0.018m. 캡슐이 소품을 밀지 않음 |
| 소품이 놓인 채 계산대에 몸 붙이기 | 움직인 물건 없음 |

### Mock 런타임 경로 (플레이어)

시뮬레이터 꺼짐, `OpenXRHmd`와 Touch 컨트롤러 2개 인식. 왼손 이동 액션은 `OculusTouchControllerOpenXR/thumbstick`, 오른손 회전 액션은 `OculusTouchControllerOpenXR1/thumbstick`에 바인딩되고 둘 다 켜져 있다. Mock은 스틱 값을 만들어 내지 못하므로 **실제 입력으로 움직이는 것까지는 확인하지 못했다.**

### 직접 본 스크린샷

플레이어 1920×1080 화면을 수치와 대조했다. 걷는 중의 비네트, 스냅 회전 중 비네트(상품 스플랫 포함), 계산대 접촉, 정면 벽 접촉(벽이 화면을 채움), 내민 채 스틱을 누른 뒤에도 계산대 앞에 남은 화면, 걷기 실행 중 계산대에 붙어 처리하는 화면. 수정 전의 "반대편으로 튄" 화면은 에디터 화면으로 봤다. 앞을 보고 있는데 계산대가 사라지고 앞벽만 보였다.

증거: `docs/p2/evidence/locomotion/`(`player/` 스크린샷과 보고서, `before_fix/`, `mock_guard.json`, 1일차·걷기·P1 보고서).

## 정해야 할 것

1. **스틱을 살짝 기울이면 더 느리다.** Starter Assets `DynamicMoveProvider`는 기울인 만큼 속도를 내고 최대가 1.5m/s다. 끝까지 밀면 사양대로지만 "고정"을 엄격히 읽으면 맞지 않는다. 키 입력은 항상 끝까지 민 값이라 시험되지 않았다. 입력을 정규화하면 어떤 기울기든 1.5가 되지만 계산대 앞 미세 이동은 어려워진다. Quest 2로 해 보고 정하는 것을 권한다.
2. **비네트가 꽤 좁다.** 샘플 기본값 0.7을 시야각 90° 화면으로 보면 가운데 원만 보인다. 기획서의 "살짝 어두워진다"보다 강해 보인다. 구현 문서는 초기값을 중간으로 두고 G1-H에서 조정하게 돼 있어 그대로 뒀다.
3. **머리 내밀기 한계 0.2m.** 벽 앞에서 머리가 벽을 넘지 않는 값으로 정했다. 계산대 너머 물건에 손이 닿는지, 더 숙일 때 세상이 밀리는 느낌이 어떤지는 실기에서 봐야 한다.

## 미완료·미검증

**Quest 2 미검증:** 조작감, 멀미(G1-H, SSQ), 실제 썸스틱 입력과 데드존, 비네트의 스테레오 표시.

**구현하지 않은 5.1절 항목:**

- `Customer` 레이어와 플레이어의 `NavMeshObstacle`. 손님 캐릭터가 범위 밖이라 뒀다. 지금 손님 도형은 충돌체가 없어 플레이어와 겹칠 수 있다. → 11/07 밤 손님 캐릭터 작업에서 추가했다(`손님캐릭터_줄서기_2026-11-07.md`).
- 계산대 "끝 통로 한 곳". 임시 계산대는 양쪽 끝이 열려 있어 손님 쪽으로 돌아갈 수 있다. 매장 배치(P3-K1) 몫이다.
- 진열대 콜라이더를 진열면보다 10cm 앞에 두기. 진열대가 아직 자리표시 상자다.

**시험하지 않은 경로:**

- 스틱 일부만 기울이기, `T`로 왼손을 선택한 조작
- 왼손으로 든 채 걷기(자동 시험은 오른손만), 걸으면서 물건 놓기. XRI는 손 움직임으로 던지므로 걷던 속도가 실릴 것으로 보이나 측정하지 않았다
- 실제로 몸을 숙였을 때. 캡슐 높이는 스틱으로 움직일 때만 머리 높이로 갱신된다

**알려진 제한:**

- 손(컨트롤러)에는 충돌이 없어 벽을 통과한다. 벽 앞에서 머리를 내밀면 컨트롤러 모델이 벽에 묻힌다.
- 머리가 0.2m를 넘어 걸어 들어가면 입력 없이 세상이 밀린다. 멀미 쪽으로 불리할 수 있으나, 벽과 계산대를 뚫는 것보다 낫다고 판단했다.

## 작업 중 발견해 고친 것

- **계산대 뚫기.** 위의 `RoomScaleBody`.
- **검증기 오류 4건, 모두 게임 문제가 아니었다.** 스냅 시험이 직전 걷기의 비네트가 사라지기 전에 시작한 것, 실제 걸음 시험의 첫걸음이 계산대 쪽이라 새 동작대로 캡슐이 먼저 멈춘 것, 몸을 내민 채 돌면 캡슐이 계산대를 따라 미끄러지는 정상 동작을 실패로 본 것, 플레이어의 머리 방향 오차 0.42° 때문에 캡슐이 x로 1mm 움직인 것을 실패로 본 것. 기준을 "계산대 안으로 들어가지 않음"으로 바로잡았다.
- **`walk.counter_contact_moves_nothing` 1회 실패.** 손님이 물건을 놓은 직후 위치를 기록했을 때 3개 중 1개가 1cm 넘게 움직인 것으로 나왔다. 당시에는 이름을 찍지 않아 무엇인지 모른다. 1.5초 기다린 뒤 기록하자 이후 4회 모두 0개였다. 캡슐은 z=0.35까지만 닿고 상품은 z≈0.68에 있으며 레이어로도 충돌하지 않으므로, 놓인 직후 자리 잡는 움직임으로 **추정**한다.
