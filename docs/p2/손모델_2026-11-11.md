# 손 모델 (2026-11-11)

> **상태: 컨트롤러 모양 대신 손이 보이고, 버튼에 따라 손가락이 움직인다. 에디터 + XR Device Simulator에서만 확인했다.** Quest 2로는 보지 않았다. 워크트리 `aaa-game-development-strategy-6d77da`의 브랜치에만 커밋했고(기준 `dc5a87a`), 메인 반영과 푸시는 하지 않았다.
>
> 발표(11/17) 범위가 아니다. "좁은 범위에서 완성도를 높인다"는 방향의 첫 단계(손과 물건)이고, 이번에 한 것은 그중 1번(손이 보이게)뿐이다.

## 1. 무엇이 바뀌었나

| 전 | 후 |
|---|---|
| 손 자리에 XRI 기본 컨트롤러 모양(흰색)이 보였다 | 사람 손과 남색 근무복 소매 끝이 보인다. 컨트롤러 모양은 숨긴다 |
| 버튼을 눌러도 보이는 것은 그대로였다 | 가운뎃손가락 버튼(그립)을 누르면 아래 세 손가락과 엄지가 접히고, 집게손가락 버튼(트리거)을 누르면 검지가 접힌다 |
| - | 무언가를 쥐고 있으면 손이 반쯤 오므려진다 |

잡기·스캔·결제 같은 규칙과 판정은 건드리지 않았다. 손에는 충돌체가 없다.

## 2. 손은 어디서 왔나

새로 내려받은 것은 없다. 이미 프로젝트에 있는 손님 캐릭터 **Microsoft Rocketbox `Female_Adult_01`(MIT)** 의 손을 잘라 쓴다. 손님과 같은 화풍이고 손가락 관절(손가락마다 3개)이 그대로 있다.

- 여성 캐릭터를 고른 이유는 텍스처다. 1024 몸 텍스처에서 손이 차지하는 영역이 여성은 약 166×451픽셀, 남성은 약 216×152픽셀이다.
- 손목에서 가운뎃손가락 끝까지 약 17cm인 것을 1.06배로 키웠다(편 상태 약 18.7cm).
- 손목 뒤 팔은 11cm만 남기고, 그 위에 소매 끝을 씌워 잘린 면을 가린다. 소매 색은 점장 앞치마와 같은 남색이다.

## 3. 만든 것

| 무엇 | 어디 |
|---|---|
| 손 프리팹을 만드는 도구(자르기, 관절·경첩 계산, 소매, 그림 뽑기) | `Assets/Editor/PlayerHandSetup.cs` |
| 손가락을 움직이는 부품 | `Assets/Scripts/Interaction/PlayerHand.cs` |
| 프리팹, 메시, 재질 | `Assets/Prefabs/Hands/`, `Assets/Art/Generated/Hands/`, `Assets/Materials/Hands/` |
| 매장 씬에 붙이기 | `P2StoreBuilder.Build`가 `PlayerHandSetup.Setup`과 `Install`을 부른다 |
| 자동 검사 항목 3개와 손 클로즈업 캡처 | `P2DayVerification.Tutorial` (`hands.*`, `02h_hand_holding.png`) |

### 손이 놓이는 자리

리그의 컨트롤러 기준점은 "가리키는 자세"이고, 그 원점에서 포크 지점과 레이가 시작된다. 그래서 **가리키는 검지 끝이 그 원점(앞으로 7.5mm)에 오고 검지가 레이 방향을 향하게** 놓았다. 손끝이 닿는 곳이 게임이 닿는 곳이다. 손등은 바깥을 보되 위로 25° 돌렸다(컨트롤러를 쥔 손처럼).

이 자리가 실제 손과 얼마나 겹치는지는 헤드셋에서만 알 수 있다. 조정값은 `PlayerHandSetup`의 `IndexTipAt`, `BackOfHandUp`, `HandScale`이다.

### 자세

각도는 `PlayerHand`의 표(`Loose`, `Fist`, `Point`)에 있고 관절마다 도 단위다.

| 입력 | 손 |
|---|---|
| 아무것도 안 누름 | 힘을 뺀 손 |
| 그립 | 주먹을 쥐고 검지만 편다(가리키기) |
| 그립 + 트리거 | 주먹 |
| 트리거만 | 검지만 접힌다 |
| 무언가를 쥐고 있음 | 반쯤 오므린 손 |

## 6. 확인하지 않은 것

- **Quest 2.** 손이 실제 손 자리에 겹쳐 보이는지, 크기가 맞는지, 소매 끝이 시야에서 어색하지 않은지, 프레임.
- IL2CPP 플레이어. 다시 빌드하지 않았다.
- 왼손으로 하는 조작. 검사는 오른손만 쓴다(왼손은 그림에서 모양만 봤다).
- 검지 끝으로 POS를 누르는 것. 검사는 레이와 트리거로 누른다. 검지 끝이 포크 지점에 오도록 놓았다는 것은 수치로만 확인했다(`hands_report.txt`).
- 손이 물건·계산대를 뚫고 지나가는 모습. 막지 않았다.

## 7. 알게 된 것과 남긴 것

- **1일차 검사의 "한 번 더 찍기" 경로가 판정 공간 모서리를 스친다.** 검사는 상품을 스캐너 옆(z=0.42)에서 유리 앞으로 가로질러 옮긴 뒤 뒤로 뺀다. 세워진 유리가 읽는 공간은 z 약 0.45부터라 바코드 면이 그 가장자리를 지난다(4번 실행의 정상 판독도 바코드 면 z=0.445에서 났다). 마우스가 조금만 움직여도 여기서 한 번 더 찍힐 수 있다. 게임 규칙은 정상이고 검사 경로의 여유가 없는 것이다. 고치지 않고 기록만 한다.
- 원인을 가리려고 검사가 스캔마다 위치를 로그로 남기게 했다(`[P2 Day] scan n: ...`).
- **손목 화면은 예전 자리 그대로다.** 왼손 옆(엄지 쪽)에 떠 있다. 손이 생겼으니 손목 위로 옮길지는 헤드셋에서 보고 정한다.
- **손 텍스처는 흐리다.** 1024 몸 텍스처의 일부라 손 전체가 약 166×451픽셀이다. Rocketbox 원본은 2048이라 받아 오면 두 배가 되지만 내려받기라 승인이 필요하다.
- 에디터 배치 실행에서는 스킨이 프레임당 한 번만 계산돼서, 한 번의 호출로 여러 자세를 그리면 전부 첫 자세로 나온다. 그림은 `BakeMesh`로 굳힌 사본을 그린다(`PlayerHandSetup.ShowPosed`).
