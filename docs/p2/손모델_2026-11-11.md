# 손 모델 (2026-11-11)

> **상태: 컨트롤러 모양 대신 손이 보이고, 쥔 물건의 모양에 맞춰 손가락이 닿고, 물건마다 다른 소리와 진동이 난다. 에디터 + XR Device Simulator에서만 확인했다.** Quest 2로는 보지 않았고, **새 소리는 아무도 듣지 않았으며 진동은 아무도 느껴 보지 않았다.** 워크트리 `aaa-game-development-strategy-6d77da`의 브랜치에만 있고(기준 `dc5a87a`, 1단계 커밋 `f2119b1`), 메인 반영과 푸시는 하지 않았다.
>
> 발표(11/17) 범위가 아니다. "좁은 범위에서 완성도를 높인다"는 방향의 첫 단계(손과 물건)이고, 지금까지 1번(손이 보이게), 2번(물건에 맞춰 쥐기), 3번(물건마다 다른 소리와 진동)을 넣었다. 2번과 3번은 커밋 전이다.

## 1. 무엇이 바뀌었나

| 전 | 후 |
|---|---|
| 손 자리에 XRI 기본 컨트롤러 모양(흰색)이 보였다 | 사람 손과 남색 근무복 소매 끝이 보인다. 컨트롤러 모양은 숨긴다 |
| 버튼을 눌러도 보이는 것은 그대로였다 | 가운뎃손가락 버튼(그립)을 누르면 아래 세 손가락과 엄지가 접히고, 집게손가락 버튼(트리거)을 누르면 검지가 접힌다 |
| 무엇을 쥐든 같았다 | 쥐는 순간 손이 물건의 가장자리로 가서, 손가락은 한쪽 면에 닿을 때까지 접히고 엄지는 반대쪽으로 돌아가 닿는다 |
| 상품은 쥘 때 소리가 없고 진동은 전부 같았다 | 봉지는 쥘 때 바스락, 손에서 돌리거나 더 쥘 때마다 바스락. 종이 상자는 툭. 내려놓으면 떨어진 속도만큼 소리가 난다. 진동도 물건마다 다르다 |

잡기·스캔·결제 같은 규칙과 판정은 건드리지 않았다. 물건은 게임이 두는 자리에 그대로 있고 **그려지는 손만 움직인다.** 손에는 충돌체가 없다.

## 2. 손은 어디서 왔나

새로 내려받은 것은 없다. 이미 프로젝트에 있는 손님 캐릭터 **Microsoft Rocketbox `Female_Adult_01`(MIT)** 의 손을 잘라 쓴다. 손님과 같은 화풍이고 손가락 관절(손가락마다 3개)이 그대로 있다.

- 여성 캐릭터를 고른 이유는 텍스처다. 1024 몸 텍스처에서 손이 차지하는 영역이 여성은 약 166×451픽셀, 남성은 약 216×152픽셀이다.
- 손목에서 가운뎃손가락 끝까지 약 17cm인 것을 1.06배로 키웠다(편 상태 약 18.7cm).
- 손목 뒤 팔은 11cm만 남기고, 그 위에 소매 끝을 씌워 잘린 면을 가린다. 소매 색은 점장 앞치마와 같은 남색이다.

### 손이 놓이는 자리 (아무것도 쥐지 않았을 때)

리그의 컨트롤러 기준점은 "가리키는 자세"이고, 그 원점에서 포크 지점과 레이가 시작된다. 그래서 **가리키는 검지 끝이 그 원점(앞으로 7.5mm)에 오고 검지가 레이 방향을 향하게** 놓았다. 손등은 바깥을 보되 위로 25° 돌렸다(컨트롤러를 쥔 손처럼).

이 자리가 실제 손과 얼마나 겹치는지는 헤드셋에서만 알 수 있다. 조정값은 `PlayerHandSetup`의 `IndexTipAt`, `BackOfHandUp`, `HandScale`이다.

### 버튼에 따른 자세

각도는 `PlayerHand`의 표(`Loose`, `Fist`, `Point`)에 있고 관절마다 도 단위다.

| 입력 | 손 |
|---|---|
| 아무것도 안 누름 | 힘을 뺀 손 |
| 그립 | 주먹을 쥐고 검지만 편다(가리키기) |
| 그립 + 트리거 | 주먹 |
| 트리거만 | 검지만 접힌다 |

### 물건에 맞춰 쥐기 (`PlayerHand.FitTo`)

쥐는 순간 한 번 계산하고, 손은 0.12초에 걸쳐 그 자리로 간다. 놓으면 같은 시간에 걸쳐 컨트롤러 자리로 돌아온다. 쥐고 있는 동안 손은 물건에 붙어 함께 움직인다.

1. **상자 고르기.** 쥔 것의 충돌체 가운데 손바닥에서 가장 가까운 상자(트리거 제외). 상자가 아니면 예전처럼 반쯤 오므린 손으로 든다.
2. **손바닥이 닿을 면.** 지금 손바닥이 가장 많이 향한 면. 납작한 물건은 넓은 두 면 쪽으로 기울고(엄지가 반대쪽으로 돌아갈 수 있어서), 카드 옆면처럼 2.5cm보다 좁은 면은 고르지 않는다.
3. **자리.** 손가락이 뻗은 방향 그대로 뒤로 가서 그 면의 가장자리를 찾고, 그 가장자리를 엄지와 검지 사이에 끼운다. 가장자리가 12cm보다 멀면 그 자리에 손바닥을 댄다.
4. **손가락.** 손가락마다 닿을 때까지 접는다. 두께 2cm 이상인 물건은 닿은 마디 바깥쪽만 더 접어 가장자리를 감싼다. 끝까지 아무것도 닿지 않는 손가락은 닿은 손가락들보다 조금 더 오므린다.
5. **엄지.** 관절 각도를 훑어, 끝이 상자에 닿고 관절이 상자에 묻히지 않는 자세를 고른다. 두께 4.5cm까지는 반대쪽 면으로 돌아가고, 더 두꺼우면 가장자리 아래 옆면에 닿는다.

| 물건 | 쥐는 모습 |
|---|---|
| 과자 봉지(두께 5~9cm) | 세워져 있으면 옆 가장자리를 손바닥으로 감싸고 엄지는 앞면, 손가락은 뒷면. 누워 있으면 윗면에 손가락, 옆면에 엄지 |
| 라면 봉지·작은 상자(두께 3~4cm) | 가장자리를 쥐고 엄지가 반대쪽 면까지 돌아간다 |
| 카드·지폐 | 손가락은 윗면, 엄지는 아랫면. 손가락이 먼 가장자리를 넘어 말리지는 않는다 |
| 동전(어느 쪽으로도 5cm 미만) | 굽힌 검지 끝과 엄지 끝 사이에 집는다 |
| 손잡이·커터(폭 6cm 이하, 길이가 폭의 1.8배 이상) | 손가락 첫 마디 아래에 가로로 놓고 감싸 쥔다. 끝 면을 쥐지 않는다 |
| 큰 상자 | 가장자리 가까이 손바닥을 대고 엄지는 옆면 |

조정값은 `PlayerHand` 위쪽의 상수들이다(손가락 두께, 두께 기준, 손이 가는 시간 등).

### 물건마다 다른 소리와 진동 (`TouchFeel`)

물건이 원래 내던 것(상품을 쥘 때의 짧은 진동, 동전의 짤랑과 지폐의 사락)은 그대로 두고 그 위에 더한다. 손을 끄면(`-show-controllers`) 예전과 똑같다.

| 물건 | 쥘 때 소리 | 쥘 때 진동 (세기 / 초) | 쥐고 있는 동안 |
|---|---|---|---|
| 봉지 상품 18종 | 바스락 (3가지 중 하나) | 원래의 0.3 / 0.05 뒤에 작은 것 4번 (0.1~0.28 / 0.012) | 초당 70° 넘게 26° 돌릴 때마다, 또는 그립을 0.12만큼 더 쥐거나 풀 때마다 바스락(4가지 중 하나)과 작은 진동. 0.11초에 한 번까지 |
| 종이 상자 상품 3종(닭다리·고래밥·아몬드 초콜릿) | 툭 (2가지 중 하나) | 0.45 / 0.02 | - |
| 카드 | - | 0.18 / 0.012 | - |
| 지폐 | (금전출납기에서 꺼낼 때 원래 소리) | 0.08 / 0.02 | - |
| 동전 | (〃) | 0.3 / 0.008 | - |
| 입고 박스 손잡이·날개 | (원래 소리) | 원래 것 뒤에 0.4 / 0.12 (무게) | - |
| 커터 | - | 0.2 / 0.02 | - |

- **내려놓는 소리.** 손에서 놓인 상품이 초속 0.3m 넘게 무언가에 닿으면 봉지는 툭-바스락, 종이 상자는 툭. 2.5m/s에서 가장 크다. 막 나타난 상품(손님이 계산대에 놓는 순간)과 봉투·진열대에 들어간 상품은 내지 않는다.
- 같은 소리가 되풀이되지 않게 여러 벌 중 하나를 고르고 높낮이를 ±7% 바꾼다.
- 소리는 전부 합성이다(받은 것 없음). 봉지는 아주 짧고 밝은 딱 소리 수십 개가 처음에 몰렸다가 잦아드는 것, 종이 상자는 낮고 짧은 울림이다.
- 수치는 전부 [제안]이다. 소리 크기와 진동 세기는 헤드셋을 쓰고 들어 봐야 맞출 수 있다. `TouchFeel` 위쪽의 상수와 `make_hand_sounds.py`에서 고친다.

## 4. 실행

```powershell
# 손 프리팹을 다시 만들고 자세를 그림으로 뽑기 (매장 없이, 약 40초)
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod PlayerHandSetup.Preview -hands-evidence <출력폴더> -quit

# 매장 물건 크기의 상자 11가지를 쥔 모습을 그림으로 뽑기 (약 40초)
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod PlayerHandSetup.PreviewGrasps -hands-evidence <출력폴더> -quit

# 손 대신 예전 컨트롤러 모양으로 실행 (비교용, 에디터와 플레이어 모두)
... -show-controllers

# 손의 소리를 다시 만들기 (둘째 인자를 주면 파형·스펙트로그램 그림과 수치 표도 쓴다)
python scripts/windows/make_hand_sounds.py Assets/Audio/Generated <확인용폴더>

# 소리와 상품 포장 정보를 지금의 매장 씬에 넣기 (씬을 다시 빌드하지 않는다. 빌드하면 조명을 다시 굽는다)
Unity.exe -batchmode -projectPath <프로젝트> -executeMethod PlayerHandSetup.InstallTouchFeelInStore -quit
```

### 자동 검사

| 검사 | 결과 | 실제 마우스 |
|---|---|---|
| 고정 1일차 `-p2-verify` | **274/274, S 98** | 49px (실패 없음) |
| 고정 2일차 `-p2-day2-verify -start-day 2` (박스 손잡이, 커터, 날개, 진열) | **361/361, A 89.0**, 예외 0 | 0 |

1일차 항목은 255개에서 274개가 됐다(2일차는 346 → 361). 더한 것:

- `hands.drawn_instead_of_the_controllers`, `hands.open_before_the_grip`, `hands.back_on_the_controller_after_letting_go`
- `hands.holds_a_thing_by_its_shape`: 포테토칩을 쥐었을 때 다섯 손가락 끝이 상품 상자에서 7~9mm(손가락 두께만큼), 상자에 묻힌 것 없음. 그려진 손은 컨트롤러에서 14cm 떨어져 있었다(검사가 컨트롤러를 상품 한가운데에 두고 쥐기 때문).
- `…sounds_and_feels_like_its_package`(상품을 쥘 때마다): 봉지는 바스락이 한 번, 종이 상자(고래밥)는 툭이 한 번 요청됐고 진동이 요청됐다(봉지 4번, 상자 1번).
- `hands.bag_rustles_as_it_is_turned`: 바코드를 찾아 돌리는 동안 바스락 0 → 3번.
- `aside.lands_with_a_sound`: 계산대 위 3cm에서 놓은 상품마다 내려놓는 소리 1번.

검사는 소리가 **요청된 횟수**와 진동이 **요청된 횟수**만 센다. 시뮬레이터에는 진동을 받을 기기가 없고, 소리는 아무도 듣지 않았다.

- 소리 자체는 파형과 스펙트로그램으로만 봤다(`evidence/hands/hand_sounds_review.png`, `.csv`). 봉지 소리는 2~15kHz의 짧은 딱 소리가 처음에 몰렸다가 잦아들고, 종이 상자는 1kHz 아래에서 0.1초 안에 사라진다. 크기는 기존 효과음과 비슷하게 맞췄다(바스락 RMS -21dB, 기존 진열 소리 -22dB, 동전 -24dB).
- 보고서: `evidence/hands/day_report_hands_on.json`, `day2_report_hands_on.json`, `day_report_controllers.json`(1단계 때 손을 끄고 돌린 비교).
- 1단계 때의 실행 기록(마우스가 움직여 실패가 섞인 두 번 포함)은 커밋 `f2119b1`의 이 문서에 있다.

돌리지 않은 것: 수습·성장, 손 진열, 타이틀, 첫 1분 검사. 일괄 테스트 때 함께 돌린다.

## 7. 알게 된 것과 남긴 것

- **손은 상품의 상자에 맞춘다.** 상품 충돌체는 실측 크기 상자이고 봉지 스플랫은 그보다 볼록하거나 들어가 있어서, 손가락이 봉지 그림에 살짝 묻히거나 뜰 수 있다.
- **쥘 때 손이 실제 손에서 떨어질 수 있다.** 검사처럼 물건 한가운데에서 쥐면 10cm 넘게 가장자리로 옮겨 가고, 손목이 최대 67° 돌아간 것처럼 그려진다. 사람은 보통 가장자리를 향해 손을 뻗으므로 덜할 것으로 보지만 헤드셋에서 봐야 한다.
- 손이 계산대나 진열대를 뚫고 지나가는 것은 막지 않았다.
- **1일차 검사의 "한 번 더 찍기" 경로가 판정 공간 모서리를 스친다.** 검사는 상품을 스캐너 옆(z=0.42)에서 유리 앞으로 가로질러 옮긴 뒤 뒤로 뺀다. 세워진 유리가 읽는 공간은 z 약 0.45부터라 바코드 면이 그 가장자리를 지난다. 실제 마우스가 조금만 움직여도 여기서 한 번 더 찍힐 수 있다(1단계 때 두 번 겪었다). 게임 규칙은 정상이고 검사 경로의 여유가 없는 것이다. 고치지 않고 기록만 한다. 검사는 스캔마다 위치를 로그로 남긴다(`[P2 Day] scan n: ...`).
- **손목 화면은 예전 자리 그대로다.** 왼손 옆(엄지 쪽)에 떠 있다. 손목 위로 옮길지는 헤드셋에서 보고 정한다.
- **손 텍스처는 흐리다.** 1024 몸 텍스처의 일부라 손 전체가 약 166×451픽셀이다. Rocketbox 원본은 2048이라 받아 오면 두 배가 되지만 내려받기라 승인이 필요하다.
- 에디터 배치 실행에서는 스킨이 프레임당 한 번만 계산돼서, 한 번의 호출로 여러 자세를 그리면 전부 첫 자세로 나온다. 그림은 `BakeMesh`로 굳힌 사본을 그린다(`PlayerHandSetup.ShowPosed`).
