# 첫 1분 개선 (2026-11-09)

> 사용자 요청: 처음 보는 유저가 1분 안에 느끼는 평가를 높이기. 제안 7개 중 1, 3, 4, 5, 6번을 진행했다.
>
> **상태: 코드, 음성, 씬 재빌드와 시뮬레이터 자동 검사까지 끝났다. Quest 2로는 보지 않았다.** 자세한 것은 4장.

## 1. 왜 바꿨나

이전의 첫 1분은 회색 문 앞의 버튼 6개 메뉴, 아무도 없는 매장 걷기, 출근 카드 꽂기로 끝났다. 손님은 튜토리얼 6단계가 끝나야 들어왔다. 강점인 사람 반응과 실사 상품이 첫 1분 밖에 있었다.

## 2. 바뀐 것

| 제안 | 내용 |
|---|---|
| 1. 사람부터 보여 주기 | 점장을 앞치마와 "점장" 명찰을 단 캐릭터로 계산대 끝에 세웠다. 문이 열리면 손을 흔들고, 플레이어를 보며 입을 움직여 안내한다. 소리는 점장 쪽에서 난다. 입장 전부터 손님 2명이 장을 보고 있다 |
| 3. 조작 때문에 멈추는 시간 없애기 | 걷는 법을 입장 순간부터 안내판과 왼손 옆에 표시한다. 보드와 음성의 "그립"을 "가운뎃손가락 버튼"으로 바꿨다. 노란 화살표(`TargetPointer`)가 다음에 만질 것을 단계 시작부터 가리킨다. 손에 든 상품의 바코드 면도 가리킨다 |
| 4. 첫 시야 채우기 | 곤돌라 D의 문 쪽 면 3단(18자리)과 곤돌라 A·B의 눈높이 단(9자리)을 실사 상품으로 채웠다. 표시 전용이라 입고와 점수에 관여하지 않는다 |
| 5. 타이틀 교체 | 회색 문을 유리문으로 바꿨다. 첫 화면에 "출근하기"와 "설정"만 두고, 2·3일차와 편의 옵션은 설정 안으로 옮겼다. 안내판을 눈높이 아래로 내려 매장과 사람이 그 위로 보인다 |
| 6. 튜토리얼을 첫 손님 응대로 | 장을 보던 손님이 계산대로 와서 인사하고 바구니를 내려놓는다. 잡기부터 카드까지 끝나면 "+금액" 카드와 함께 고맙다고 하고 떠난다. 현금은 다음 손님이 맡는다. 이 두 손님은 1일차 주문 5건과 매출에 넣지 않는다 |

함께 고친 것: "튜토리얼 완료" 문구가 바로 덮여 보이지 않던 버그. 이제 4초 보이고 점장이 "은행 좀 다녀올게요" 하고 정문으로 나간다.

음성: `voice_tutorial_1`, `voice_tutorial_6`을 다시 만들고 `voice_manager_first_customer`, `voice_manager_alone`을 추가했다. 여전히 Windows TTS이고 청취는 안 했다.

## 3. 코드 지도

- 점장: `Assets/Scripts/Gameplay/ManagerNpc.cs`, 위치는 `P2StoreBuilder`의 `Manager Spot`
- 화살표와 손 옆 안내: `TargetPointer.cs`, `ControllerHint.cs`
- 미리 온 손님과 튜토리얼 손님: `CustomerDirector.StartAmbient`, `CallGuest`, `BringGuest`, `GuestLeaves`
- 튜토리얼: `TutorialController.cs`
- 타이틀과 유리문: `TitleFlow.BuildPanel`, `P2StoreBuilder.GlassLeaf`
- 표시 전용 진열: `P2StoreBuilder.BuildDecorSlots`, `IntakeDirector.StockDecor`, `ShelfSlotZone.DisplayOnly`·`FarOnly`, `P4ShelfSplats`(이미 만든 칸은 건너뜀)
- 검사: `-p2-intro-verify` (`P2TitleVerification.RunIntroCheck`)

병합본을 다시 만들려면 `P2StoreBuilder.Build` → `P4ShelfSplats.Generate` → `P2StoreBuilder.Build` 순서로 돌린다. 경량본 PLY가 `capture/lod`에 있어야 한다.

## 4. 검증

모두 에디터와 XR Device Simulator다. 다른 곳에서 돌던 `ns-train` 3개가 끝나 GPU가 빈 뒤(11/09 19:52~20:40)에 돌렸고, 외부 마우스 입력은 모두 0이다. 데스크톱 프레임은 200~330fps로 VR 수치가 아니다.

| 검사 | 결과 | 비고 |
|---|---|---|
| `P2StoreBuilder.Build`, `P4ShelfSplats.Generate` | 통과 | 새 9칸 근거리 629,112, 원거리 539,490 가우시안 |
| `-p2-intro-verify` | 72/72 | 순간 이동 0 |
| `-p2-title-verify` | 75/75 | 설정 접기, 유리문 충돌, 입장 안내, 출근 카드 포함 |
| `-p2-verify` (1일차) | 206/206 | S 98점, 매출 13,500/13,500원, 이탈 0 |
| `-p2-day2-verify -start-day 2` | 299/299 | A 89.5점, 매출 19,000/20,500원, 표본 시점 최대 1,369,228 가우시안(렌더러 17개) |
| 화면 확인 | 양호 | 타이틀, 문 열림, 입장, 곤돌라 D, 첫 손님, 바코드 화살표, 감사 인사, 현금, 완료, 정산을 캡처로 봤다(`docs/p2/evidence/first_minute/`, `day1/editor`, `day2/editor`, `title/editor`). 정지 화면만 |

타이틀과 1일차는 아래 전환 거리 수정 전에 돌렸다. 바뀐 것은 어떤 복사본을 그리느냐뿐이고 게임 규칙은 그대로다.

첫 1분과 타이틀 실행은 결과를 쓴 뒤 에디터 종료 단계(`Cleanup mono`)에서 0xC0000005로 끝났다. 11/08부터 있던 종료 충돌이고 결과에는 영향이 없다.

**가우시안 예산.** 처음에는 2일차의 `p4.peak_gaussians_in_budget`만 실패했다(1,557,457, 기준 150만). 표시 칸 원거리본이 항상 539,490을 더하는데, 사진 기준 재배치로 진열대 A와 B가 한 줄로 붙어 3m·4m 경계에서 근거리본이 많이 켜져 있었다. 작업 칸의 경계를 2.4m·2.8m로 줄여 해결했다. 진열은 1m 안쪽에서 하고, 계산대에서는 모든 칸이 경계 밖이라 원거리본이다.

표시 칸은 작업 칸이 하나라도 가까우면 원거리본에 머물게 했다. 이것만으로는 표본 최대가 바뀌지 않았지만(1,557,457 그대로), 진열대 사이 통로에서 일할 때 곤돌라 D의 근거리본이 등 뒤에 켜지는 것을 막는다.

표본은 진열 직후와 주문 완료 직후에만 뜬다. 상품을 손에 들고 미리보기가 켜진 순간은 재지 않았고, 계산으로는 약 150만 안팎이다.

하지 않은 것: Quest 2, 72fps 측정, 3일차, IL2CPP 플레이어 재빌드(`Builds/Store`는 예전 그대로), 새 음성 청취.
