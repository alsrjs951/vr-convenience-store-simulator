# 닭다리 V01 검증 · 배경 분리 · 보충 촬영

> 후속 갱신: 실물 없이 기존 자료를 10,000회 학습한 결과 윗면 표현이 크게 개선됐다. **윗면 즉시 재촬영은 보류 가능**, 바닥면·치수는 여전히 미확인. 사용할 최신 에셋과 비교 결과는 [기존 자료 품질 개선 보고서](닭다리_기존자료_품질개선_2026-11-06.md) 참조.

## 판정

**다른 영상 V01로 윗면의 형태를 확보했고, 상품을 배경에서 분리한 개발용 PLY를 만들었다.** V02와 합치지 않고 V01을 독립적으로 처리했다. 원본 영상, V02 결과, V01 전체 장면 결과는 보존했다.

윗면의 작은 글씨·광택 부분에는 거친 스플랫과 흐림이 남는다. 바닥 접촉면은 관측되지 않았으므로 완전한 6면 에셋으로 판정하지 않는다. 전체 재촬영보다 아래의 한정된 보충 촬영을 권장한다.

평가 수치는 **배경 포함 전체 장면**에 대한 것이다. 배경 분리 후 품질 지표가 아니며 V02와 평가 이미지/학습량이 달라 직접적인 우열 비교에 쓰지 않는다. 같은 영상 내 시점 분할이며 새로운 독립 촬영 검증은 아니다. 오프라인 렌더 FPS는 HMD 성능이 아니다.

## 배경 분리 방법 및 한계

1. 16개 학습 시점에서 붉은 상자 영역의 볼록 외곽선을 추출하고 작은 여유 폭을 줬다. [외곽선 검토](evidence/dakdari_isolated/silhouette_review.jpg).
2. 각 Gaussian 중심을 카메라에 투영했다. 최소 6시점에서 보이며 유효 시점의 90% 이상에서 외곽선 안에 있는 것만 남겼다.
3. 남은 중심의 DBSCAN 최대 연결 군집만 보존해 떨어진 배경 점들을 추가 제거했다(eps=강건 범위의 2.5%, min_samples=12).
4. 여러 시점에서 렌더해 상품과 배경 분리를 육안 확인했다. 작은 테두리 잔상과 윗면의 가는 가시 형태는 여전히 남는다. 윗면의 거친 표현은 분리 전 원본 모델에도 있으므로 전부 잘라내기 탓으로 볼 수 없다.

이 방법은 **붉은 상자형 닭다리에 맞춘 휴리스틱**이다. 다른 상품에 그대로 적용하지 않는다. Gaussian 중심만 필터링하므로 Gaussian 자체가 뻗는 범위까지 잘라내지는 않는다. 가려진 바닥을 새로 만들어 넣지도 않았다.

스크립트: `scripts/windows/isolate_dakdari.py <config.yml> <전체 PLY> <출력 폴더>`. 입력·체크포인트를 변경하지 않고 별도 PLY와 검토 이미지를 출력한다. [분리 설정/개수](evidence/dakdari_isolated/isolation.json).

## 사용 위치

- 원본 결과: `capture/products/capture_01/session_v01/`
- 분리 PLY: `capture/products/capture_01/session_v01/isolated/dakdari_isolated.ply`
- Unity 에셋: `Assets/GaussianSplats/DakdariIsolated/dakdari.asset`
- Unity 씬: `Assets/Scenes/DakdariIsolated.unity`
- Unity 6000.3.26f1 / RTX 4070 / DX12에서 34,417개 렌더 확인. 침구 대신 Unity 기본 배경이 보이며, 시뮬레이터 W 입력 이동 0.2000 재구성 단위 PASS. [화면](evidence/dakdari_isolated/unity/trained_before.png), [검증 기록](evidence/dakdari_isolated/unity/trained_runtime.txt). C# 예외는 확인되지 않았다. HMD/OpenXR 런타임 실기 검증은 기존과 같이 미완료다.
- 기존 Windows 실행 파일은 이번 새 에셋/씬으로 재빌드하지 않았다.

## 보충 촬영 체크리스트

| 우선순위 | 필요한 것 | 촬영 방법 / 완료 확인 |
|---|---|---|
| 필수: 전체 방향으로 잡아 돌릴 상품 | 바닥 접촉면 | 바닥이 보이도록 배치한 **별도 세션**을 촬영. 이미 확보한 옆면도 함께 보이도록 겹치는 경로를 확보. 물체 배치가 바뀌므로 기존 영상과 바로 합치지 않음. |
| 권장: 라벨 품질 | 윗면 인쇄·광택 | 상품 고정, 강한 반사 없는 확산광에서 중간 높이→윗면으로 천천히 이동. 상자 모서리·옆면을 함께 프레임에 유지. 글씨 부분에 하얀 반사로 내용이 사라지지 않는지 확인. |
| 권장: 바코드 표현 | 바코드 면 | 초점이 맞는 정면 사진 1장과 가까운 사선 시점 여러 장/짧은 영상. 지나치게 가까워 일부만 잘리지 않도록 하고 흔들림 확인. 바코드 번호도 별도 기록. |
| 필수: 실제 크기 | 가로·세로·두께 | 자로 치수를 mm 단위로 기록. 기존 재구성 좌표는 실제 미터가 아니므로 이 정보로 Unity 크기를 맞춤. |

우선 휴대폰 원본이 남아 있는지도 확인한다. 파일명만으로 메신저 압축 여부를 단정할 수는 없다. 원본에 세부 정보가 더 있다면 새 촬영 전에 원본으로 품질을 비교할 가치가 있다.

3,000회 학습은 개발용 중간 결과다. 작은 글씨 품질은 더 긴 학습으로도 재평가할 수 있다. 그러나 촬영하지 않은 바닥과 반사로 완전히 가려진 인쇄 내용은 학습 횟수를 늘리는 것만으로 검증할 수 없다.
