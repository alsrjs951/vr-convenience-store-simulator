# 추가 촬영 상품 3DGS 제작과 매장 등록 (2026-11-10)

2026-11-08에 찍은 영상 19개(캡처 10건)로 새 상품 9종을 만들어 게임에 넣은 기록이다. 메인에 커밋한 뒤 첫 1분·글자·조명·UI·음성 작업 브랜치(`claude/improve-in-game-ai-slop-5adec0`, de56246)와 합쳤다. 푸시는 하지 않았다.

## 결론

| 구분 | 상태 | 근거 |
|---|---|---|
| **실험 성공** (만들어졌나) | 성공. 세션 19개 모두 프레임 100% 등록, 30,000회 학습 완료, 상품 9종 프리팹 생성 | 세션별 평가 PSNR 28.7~33.1. 집기 검사 9종 모두 48/48 |
| **실제 품질** (쓸 만한가) | 앞뒷면 인쇄는 읽힌다. 봉지 옆면은 번진다. 멀리서 보이는 경량본(개당 2만 개)은 글자가 흐리다 | 6방향 렌더와 게임 화면 캡처를 눈으로 확인 (`evidence/new_products_2026-11-10/`) |
| **HMD** | **검증하지 않았다** | 시뮬레이터 검사만 했다. 플레이어 재빌드도 하지 않았다 |

크기, 무게, 가격은 전부 **임시값**이다. 폭만 정해 두고(봉지 20cm, 상자 15cm) 나머지는 복원 비율을 따랐다.

## 제작 설정

4fps 선명 프레임 선택, 전수 매칭, 1080p, splatfacto 30,000회, 옵션 없음. 양파링 뒷면 상품 영역에서 bilateral grid, 카메라 최적화(SO3xR3), scale 정규화를 비교했으나 뚜렷한 이득이 없었다(PSNR 23.0~26.4, 글자 선명도는 눈으로 거의 같음). 영상당 21~33분이 걸렸다. **학습은 한 번에 하나만 돌린다.** 동시에 돌리면 12GB VRAM을 넘겨 사실상 멈춘다.

## 게임 반영

- **진열:** 표시 전용 9칸(거리 쪽 D열 6칸, A·B열 눈높이 3칸)에 3개씩 놓았다. 표시 진열 구조는 첫 1분 개선 브랜치(`claude/game-first-impression-e7be6a`, a026078)와 같은 코드를 메인에 옮겼고, 상품만 새 상품으로 바꿨다.
- **주문:** `Data/scenarios.csv`의 12건을 새 상품으로 바꿨다. 현금 주문 합계는 5,000원 이하로 유지했다.
- **카탈로그:** 12종에서 21종이 됐다.

## 이번에 고친 것

- `merge_bag_shells.py --box-thickness`: 상자는 둘레에 봉합선이 없어 봉지 방식이면 옆면이 잘려 두께 0.7cm 판이 됐다. 윗면 기준으로, 세션별로 실제 찍힌 옆면 깊이에 비례해 맞닿는 높이를 정한다.
- `P1InteractionTrial.BarcodeThickness`: 얇은 상품은 바코드 판 두께를 줄인다(최대 2cm, 상품 두께의 1/4). 두께 2.2cm 상자에서 2cm 판을 쓰면 검사용 스캐너가 3mm로 줄었다.
- `P1InteractionVerification` 스캐너 접근 경로: 시뮬레이터 손은 시야 평면을 먼저 맞추므로 내려오는 동안 스캐너 쪽으로 쏠린다. 높고 얇은 상품에서 뒷면 바코드 판이 스쳐 스캔되어, 그만큼 여유 거리를 둔다. 검사 경로만의 문제다.
- `SplatShelfSlot`: 표시 진열은 자기 진열대 등판 뒤에서는 그리지 않는다. A·B열에서 일할 때 D열 36만 개를 아낀다. 스플랫 최대치가 158만에서 122만이 됐다(목표 150만).
- `Run-ProductSession.ps1`: COLMAP이 모델을 여러 개 만들면 가장 큰 모델을 쓴다. 학습 완료는 마지막 체크포인트로 판단한다.
