# 상품 3DGS 품질 개선 (2026-11-12)

11/07에 보류했던 품질 개선을 사용자 요청으로 다시 시작한 기록이다. 기존 영상을 더 길게 다시 학습하는 일과, 사용자가 11/12 새벽에 낮은 각도로 다시 찍은 영상 9개를 기존 영상과 함께 쓰는 일을 했다.

가장 중요한 발견은 다섯 가지다.

1. **낮은 각도 영상만으로는 부족하다.** 11/12 영상은 옆면·테두리·아래쪽 그림을 훨씬 깨끗하게 복원하지만, 봉지 위쪽의 큰 상품명은 오히려 뭉개진다. 정면에서 내려다본 장면이 없어서 광택 면에 비친 조명이 형상에 굳는다. 색의 시점 의존 성분(SH)을 잘라도 그대로였다.
2. **두 날짜의 영상을 한 번에 복원할 수 있다.** 상품이 놓인 자리가 달라 배경은 맞지 않지만, 프레임마다 상품 마스크를 만들어 COLMAP과 학습이 상품만 보게 하면 두 영상의 카메라가 한 모델로 전부 등록된다(봉지 6종 모두 100%).
3. **통째로 합치면 안 되고, 11/08 영상은 상품명 부분만 기여하게 해야 한다.** 통째로 합치면 11/08 영상에 조명이 비쳤던 구역이 반투명해진다. 11/08 영상의 마스크를 상품명이 있는 위쪽으로 제한하면 상품명은 또렷하고 나머지도 깨끗하다.
4. **모양이 변하지 않는 상자는 여러 영상을 통째로 합치면 된다.** 닭다리는 세워 찍은 10/25 영상 둘과 눕혀 찍은 11/12 영상을 합쳐, 한 영상으로는 볼 수 없던 뒷면과 밑면까지 여섯 면이 모두 나왔다.
5. **등록률 100%가 복원 성공은 아니다.** 고래밥은 전수 매칭에서 137장이 전부 등록됐는데도 상자가 두 벌로 복원됐다. 순차 매칭으로 바꾸니 정상이었다.

## 방법

### 1. 기존 영상 재학습

기존 12종은 3fps·순차 매칭·10,000회였고 그중 닭다리·고래밥·포테토칩은 960×540이었다. 새 9종(11/10)과 같은 설정(4fps 선명 프레임, 전수 매칭, 1080p, 30,000회)으로 다시 학습했다. 결과는 `capture_NN/session_<면>_30k`에 따로 두어 기존 세션을 덮어쓰지 않았다.

- **포테토칩(960×540 → 1080p):** 뚜렷이 좋아졌다. 뒷면 바코드 숫자("8 801043 005821")와 유통기한 스티커가 읽힌다.
- **신라면(1080p 10,000회 → 30,000회):** 작은 글자는 조금 선명해졌지만 왼쪽 아래 검은 구석이 비쳐서, 뚜렷이 낫지 않다. **교체하지 않았다.**

### 2. 두 영상 공동 복원: `scripts/windows/prepare_joint_session.py`

같은 면을 찍은 두 영상(11/08 위에서, 11/12 낮게)을 하나의 복원으로 만든다.

1. 영상마다 이미 만들어 둔 단독 복원에서 분리한 상품(`isolated.ply`)을 그 영상의 모든 학습 카메라로 렌더해 상품 마스크를 만든다(불투명도 0.5 이상, 구멍 메우기, 가장 큰 덩어리, 6픽셀 넓힘).
2. 두 영상의 프레임과 마스크를 한 폴더에 모아 COLMAP을 돌린다. 특징점은 마스크 안에서만 뽑는다(`--ImageReader.mask_path`).
3. nerfstudio 데이터의 프레임마다 `mask_path`를 넣는다. splatfacto는 마스크 밖 픽셀을 손실에서 뺀다.
4. `--variant topA --region a=<11/08 앞면 box_fit>=<낮은 쪽>:<높은 쪽>`을 주면 11/08 영상의 마스크를 인쇄 높이의 그 구간으로 제한한 두 번째 마스크 세트와 `transforms_topA.json`을 만든다. 카메라 자세는 그대로다.

**가정:** 두 촬영 사이에 상품 모양이 그대로여야 한다. 봉지가 찌그러졌다면 겹쳐 보이거나 흐려진다. 이번 6종에서는 겹침이 보이지 않았다.

인디안밥으로 세 가지를 비교했다.

| | 상품명·로고 | 정면 아래쪽 | 옆면·테두리 |
|---|---|---|---|
| 11/08 영상만 (교체 전 모델) | 읽힘 | 초록 얼룩 | 번짐 큼 |
| 11/12 영상만 | 뭉개짐 | 깨끗함 | 깨끗함 |
| 두 영상 통째 | 또렷함 | 반투명, 뒷면 글자가 비침 | 깨끗함 |
| **11/08은 위쪽만 (`topA`)** | **또렷함** | **깨끗함** | **깨끗함** |

### 3. 뿌연 조각 제거: `build_bag_product.py --remove-haze`

결합한 뒤 불투명도 0.15 미만이거나 가장 긴 반경이 상품 폭의 5%를 넘는 Gaussian을 지운다. 봉지 둘레에 희뿌옇게 번지던 빛이 대부분 사라진다. 더 세게(0.3, 3%) 하면 면에 구멍이 생긴다.

- `all`은 어디서나 지운다. 번짐은 사라지지만 뒷면의 어두운 부분이 조금 얼룩질 수 있다(인디안밥·양파링 뒷면).
- `outside`는 면 안에 놓인 작은 것은 남기고 면 밖으로 삐져나오는 것만 지운다. 얼룩은 덜하지만 번짐이 대부분 남았다.
- 교체한 상품은 모두 `all`을 썼다.

### 4. 그 밖에 고친 것

- `build_bag_product.py --keep-manifest`: 이미 게임에 있는 상품을 다시 만들 때 매니페스트(이름·가격·크기)를 그대로 둔다. `--no-install`은 Assets를 건드리지 않고 `capture/products/<캡처>/merged`에 결합만 한다.
- `P1InteractionTrial.BuildFromArgs -p1-reimport-splat`: 스플랫 에셋이 이미 있어도 새 PLY에서 다시 만든다. `.meta`는 그대로라 프리팹과 씬의 참조가 유지된다. 이 인자가 없으면 예전 에셋을 그대로 쓴다.

### 고래밥: 전수 매칭이 상자를 두 벌로 만들었다

고래밥을 새 설정 그대로(전수 매칭) 다시 학습하니 137장이 전부 등록됐는데도 뒷면(게임 카드 면)이 뭉개졌다. 분리 전 장면에 상자가 두 군데 나타났고, 분리 범위(`--hull-margin`)를 0.12까지 넓혀도 뒷면은 돌아오지 않았다. 초록 면들이 서로 비슷해 멀리 떨어진 프레임끼리 잘못 짝지어진 것으로 본다(추정). **등록률 100%로는 알 수 없는 실패였다.**

예전처럼 이웃 프레임끼리만 맞추는 순차 매칭(겹침 12)으로 바꾸니 앞·뒤·양 끝·윗면이 모두 제대로 나왔다(137장 등록). 닭다리는 전수 매칭에서도 문제가 없었다. 면들이 서로 닮은 상자는 순차 매칭을 쓰고, 어느 쪽이든 여섯 방향 렌더로 확인한다.

11/12 고래밥 영상(9.6초)은 쓰지 않았다. 상자가 뜯긴 상태의 정면만 거의 고정된 시점으로 찍혀 있고, 정면은 기존 모델에서도 괜찮다.

### 안쪽 받침: `build_bag_product.py --liner`

어둡거나 광택 있는 면은 반투명하게 복원돼서 반대쪽 면의 인쇄가 거울처럼 비친다(꼬깔콘 군옥수수맛의 갈색 바탕). `--liner=front`는 앞면 안쪽 2%(폭 기준) 아래에, 격자 칸마다 그 칸의 반투명 Gaussian 평균색으로 칠한 불투명한 납작한 Gaussian을 하나씩 깐다. 비치는 곳에서 반대쪽 인쇄 대신 그 면 자신의 흐린 색이 보인다.

- **복원된 내용이 아니라 채워 넣은 것이다.** 면이 불투명한 곳에서는 가려진다.
- `--liner=both`는 쓰지 않았다. 뒷면의 어두운 글자판이 하얗게 떴다.
- 꼬깔콘 군옥수수맛에만 썼다.

## 다음 촬영 제안

이번 결과로 보면 한 면을 이렇게 찍는 것이 가장 좋다. 1번과 2번은 이번 비교에 근거가 있고 3번은 시험하지 않았다.

1. **낮은 각도 한 바퀴와 위에서 내려다본 한 바퀴를 한 영상에, 상품을 건드리지 않고 이어서** 찍는다. 이번에는 두 날짜의 영상을 마스크로 억지로 합쳤는데, 한 영상에 다 있으면 그럴 필요가 없다.
2. **뒷면도 같은 방식으로** 찍는다. 이번에 좋아지지 않은 곳은 모두 뒷면 쪽이다.
3. 광택 면에 조명이 크게 비치는 구간을 줄이려면 조명을 옆으로 옮기거나 확산시킨다.

## 재현

프로젝트 루트에서 nerfstudio 환경으로 실행한다. 대기열·시험 결합·설치 스크립트는 `capture/retrain_queue/`에 있다(깃 제외).

```powershell
# 새 영상 한 개 (기존 세션 폴더와 겹치지 않게 session_front_30k)
scripts\windows\Run-ProductSession.ps1 -Video <영상> -Session capture\products\<캡처>\session_front_30k -Experiment <이름> -Fps 4 -SharpFrames -Matcher exhaustive -SaveEvalImages -Variant base30k -Iterations 30000
python scripts\windows\isolate_product.py <세션>\export-ds1-base30k\splat.ply <세션>\isolated

# 두 영상 공동 준비와 상품명 구간 변형
python scripts\windows\prepare_joint_session.py capture\products\<새 캡처>\session_joint --source a=<11/08 세션>=<그 학습 폴더>=<11/08 isolated.ply> --source b=<11/12 세션>=<그 학습 폴더>=<11/12 isolated.ply>
python scripts\windows\prepare_joint_session.py <같은 인자> --variant topA --region a=<11/08 box_fit.json>=0.47:1.0
ns-train splatfacto --data capture\products\<새 캡처>\session_joint\nerfstudio\transforms_topA.json --max-num-iterations 30000 ... nerfstudio-data --downscale-factor 1

# 결합과 설치 (매니페스트 유지)
python scripts\windows\build_bag_product.py <id> --capture <결합 폴더 이름> --name x --scene x --front <앞 분리 폴더> --back <뒤 분리 폴더> --front-top=<방향> --back-top=<방향> --remove-haze=all --keep-manifest
Unity -batchmode -quit -executeMethod P1InteractionTrial.BuildFromArgs -p1-manifest Assets/Data/Provisional/<id>.json -p1-reimport-splat
Unity -executeMethod P1InteractionTrial.VerifyEditor -p1-verify -p1-scene <매니페스트의 scene>
```

주의할 점:

- `Enter-Nerfstudio.ps1`을 한 PowerShell 프로세스에서 네 번쯤 켜면 `vcvarsall`이 "The input line is too long"으로 실패한다. 대기열은 세션마다 새 프로세스로 돌린다.
- PowerShell 5.1에서 `*>&1`로 출력을 받으면 `vswhere.exe` 경고 한 줄이 오류로 바뀌어 스크립트가 멈춘다.
- 공동 복원 결과의 축 방향은 단독 복원과 다르다. 앞면 위쪽 방향은 결합 렌더를 보고 다시 정한다(감자깡·죠리퐁은 반대로 나왔다).
- 면들이 서로 닮은 상자(고래밥)는 `-Matcher sequential`로 돌린다. 전수 매칭은 등록률이 100%여도 상자를 두 벌로 만들 수 있다.
- Unity 단계는 Unity Hub가 켜져 있어야 한다. 꺼져 있으면 라이선스 오류(종료 코드 198)로 끝난다.
