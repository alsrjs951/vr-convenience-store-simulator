## 2. 어떻게 만들었나

### 2.1 경량본: `scripts/windows/make_splat_lods.py`

SuperSplat 수동 축소를 대신한다. 가까이 있고 색이 비슷한 가우시안을 합쳐 위치·크기·색의 평균을 유지한다. 색 구간을 군집 기준에 넣어서 인쇄 글자의 경계가 번지는 것을 줄였다.

| 단계 | 가우시안 | 쓰는 곳 | 원본 대비 PSNR(평균 / 최저) | 단순 삭제 방식(평균 / 최저) |
|---|---|---|---|---|
| near | 50,000 | 병합 칸 앞줄 | 32.3 / 24.8 dB | 27.1 / 20.5 dB |
| lod1 | 35,000 | 병합 칸 뒷줄, 박스 속, 미리보기 | 27.8 / 23.4 dB | 22.6 / 16.9 dB |
| far | 20,000 | 멀리서 보는 병합 칸 | 23.6 / 20.3 dB | 19.3 / 15.1 dB |

상품 11종, 각 단계를 쓰는 거리(40cm~3.5m)의 두 시점에서 gsplat으로 렌더링해 원본과 비교했다. 신라면은 그림으로도 확인했다. 닭다리는 진열 칸에 없어 경량본을 만들지 않았다.

### 2.2 칸 병합: `Assets/Editor/P4ShelfSplats.cs`

한 칸에는 한 상품만, 같은 방향으로 놓인다. 그래서 병합본은 상품의 가우시안을 자기 좌표계에서 자리 간격만큼 옮겨 이어 붙인 것이다. 회전을 하지 않으므로 보는 방향에 따른 색(구면조화)도 그대로 맞다.

- 근거리 `Shelf_{칸}_LOD0`: 앞줄 near + 뒷줄 lod1, Unity Medium 품질
- 원거리 `Shelf_{칸}_LOD1`: 전부 far, Unity VeryLow 품질
- 상품 경량본 `{id}_LOD1`: VeryLow 품질
- 자리 부피(상품 상자 + 옆 9mm, 위 6cm, 아래 2cm) 밖의 점은 병합 때 버린다. 버려진 점은 0.3% 미만이다.

### 2.3 게임 연결: `Assets/Scripts/Rendering/SplatShelfSlot.cs`

- 게임 규칙은 그대로 일반 상품 프리팹이 맡는다. 진열 중에는 상품 자신의 스플랫을 꺼 두고 병합본이 대신 그린다.
- 손으로 집으면 그 자리의 컷아웃을 켜서 병합본에서 숨기고, 상품 자신의 원본 스플랫을 켠다. 되돌아오면 반대로 한다.
- 입고 칸은 아침에 모든 자리가 숨겨져 있고, 진열할 때마다 한 자리씩 보인다.
- 플레이어가 칸에서 3m 안에 들어오면 근거리 본, 4m 밖으로 나가면 원거리 본으로 바꾼다. 한 프레임에 한 칸만 바꾼다.
- 계산대는 진열대에서 약 3.3~3.8m라 두 기준 사이에 있다. 그래서 진열대에 다녀온 뒤에는 그 칸이 계산대에서도 근거리 본으로 남는다.
- 첫 시도에서는 빈자리에 봉지 윗부분과 부유 점이 남았다(11/09 캡처). 자리 부피를 넓히고 밖의 점을 잘라 해결했다.

## 3. 다시 만드는 순서

상품 PLY가 바뀌면 다음을 다시 실행한다. `capture/lod`는 Git에 들어가지 않는다.

```text
python scripts/windows/make_splat_lods.py Assets/GaussianSplats/Products capture/lod --ids <상품 id들> --fits Assets/Data/Provisional --evaluate --sheets capture/lod/sheets
Unity -batchmode -quit -projectPath <프로젝트> -executeMethod P2StoreBuilder.Build
Unity -batchmode -quit -projectPath <프로젝트> -executeMethod P4ShelfSplats.Generate
Unity -batchmode -quit -projectPath <프로젝트> -executeMethod P2StoreBuilder.Build
```

전후 프레임을 비교할 때 `-individual-shelves` 인자를 주면 예전처럼 상품마다 그린다.

## 4. 검증

전부 2026-11-09, 에디터 + XR Device Simulator + 가상 입력이다. 재미와 착용감, 실제 프레임은 이 검사로 알 수 없다.

| 항목 | 결과 |
|---|---|
| 1일차 + 다음 날 `-p2-verify -p2-next-day` | 201/201, 외부 마우스 0 |
| 타이틀 `-p2-title-verify` | 72/72, 외부 마우스 0 |
| 2일차 아무것도 안 하기 `-p2-day2-idle` | 20/20, 외부 마우스 0 |
| 2일차 `-p2-day2-verify` | 299/299, 외부 마우스 0. 표본 시점 최대 867,987 가우시안, 렌더러 10개 |
| 화면 확인 | 1일차 진열대 A, 2일차 입고 칸(상품 2개 진열, 나머지 빈자리 깨끗함)을 캡처로 직접 봤다 |

2일차 검사에 병합 전용 항목 7개를 더했다: 시작 때 칸 상태, 손에는 원본, 미리보기는 경량본, 진열 뒤 병합본이 표시, 집으면 숨김, 돌아오면 다시 표시, 하루 끝 칸 상태와 가우시안 예산.

하지 않은 것: Quest 2, 프레임 측정(S1·S2·S1b), 3일차 플레이, IL2CPP 플레이어 빌드, 자유 이동·순차 등장·P1 회귀.

## 5. 남은 일

- Quest 2 유선으로 S1·S2·S1b를 측정한다. 단계별 비교(개별 → 병합 → 컷아웃·LOD)는 `-individual-shelves`로 할 수 있다.
- 3m·4m 경계에서 본이 바뀔 때 눈에 띄는지와, 깨울 때 프레임이 튀는지를 Quest 2에서 본다.
- 진열대의 나머지 칸과 냉장고는 아직 상품 대신 운송 상자다. 예산에 여유가 생겼으므로 채울 수 있다.
- 칸에 들어가지 않은 닭다리는 경량본이 없어 박스·미리보기에 쓰이면 원본으로 그려진다(지금 입고 대상은 신라면·고래밥뿐이다).
